# 阶段 3：翻译、结果面板与设置的真机验收整改规格

> 本文把主人于 **2026-08-09** 使用 `./scripts/dev.ps1 -Launch debug` 进行真机验收时发现的问题，收束为下一轮开发的实施与验收依据。本文只记录需求、现状证据、设计决策与验证方式；本轮**不修改应用代码**。

## 目标与边界

下一轮的目标不是继续扩展 provider 数量或精讲能力，而是先让主旅程可靠可用：

```text
快捷键框选 → OCR 原文可查看/编辑 → 翻译为目标语言 → 结果卡始终可见
                                      ↘ 设置可安全修改且立即生效
```

必须同时达成：

- 用户首次看到的按钮、文案和窗口层级符合「三秒看懂」的定位；
- OCR 原文可真正获得键盘焦点、编辑后可再次翻译；
- 默认翻译明确以当前 `target_language` 为目标，且翻译提示词可由用户配置；
- 配置档切换、重命名、保存、热键和版本信息都不会造成数据丢失或意外关闭结果；
- 项目根目录保留可审阅的非敏感 `config.yaml` 模板，Debug 与发布物均获得它的副本。

本轮不包含本地 GGUF 翻译、精讲实现、剪贴板翻译的完整交互和图像原位译文覆盖。

### R6 本轮实现记录

- `ProviderProfile.Id` 继续作为稳定内部索引、活动档值和 DPAPI 密钥文件名，设置页不再把它当作用户显示名称。

- 新建/复制配置档生成新的稳定 ID，不复制 API Key；重命名只修改 `name`，不会迁移或删除原有密钥。
- 自测覆盖了旧配置名称迁移、名称去重、稳定 ID 与活动档保持，以及设置副本保留名称。

### R2 本轮实现记录

- 结果卡改为 `Topmost`、手动定位和 `ShowActivated=False`：首次展示仍保留 `WS_EX_NOACTIVATE`，不会抢走截图前正在使用的窗口。
- OCR/视觉模式均将相对于虚拟桌面的选区传给结果卡；结果卡用物理像素坐标贴在选区下方，若下方工作区不足则翻到上方，并始终约束在选区所在显示器的工作区内。

### R9+R10 本轮实现记录

- 新增 `SettingsLayout`：各设置页统一使用「标签列 AutoSize + 输入列 Percent(100)」的 `TableLayoutPanel`，行高一律 `AutoSize`，不再有硬编码 `SetBounds` 坐标。这正是缩放错位的根因——原实现按 96 DPI 的固定像素排布，字体一放大控件就与标签互相错位。
- 字段标签改为填满单元格并垂直居中，宽度仍按文字实际需要；输入控件的自然高度随字体增长的幅度与标签不同，只有让标签跟着行高伸展，两者中心线才会一致。
- 说明与状态文字（流程说明、连接结果、提示词说明）改为可换行 `Label`，并随面板宽度更新最大宽度；多行提示词按当前字体行高定高，不再是像素常量。
- 设置窗尺寸与按钮最小宽度按 `DeviceDpi` 换算，底栏改为 `AutoSize`。已在 9/13.5/18pt（约 100%/150%/200%）下逐行核对：标签与输入框中心线偏差为 0，无控件高度小于其首选高度。
- 热键页移除自由文本框，改为只读录制框：点击当前热键即进入录制（聚焦后按 Enter/空格同样可进入，保证键盘可达），不再有多余的「录制」按钮。进入录制显示「请按下快捷键，Esc 取消」，按住修饰键时实时回显 `Ctrl+Shift+…`，补上普通键后显示规范化组合（如 `Ctrl+Shift+Q`）。
- 录制必须在 `WndProc` 处理原始键盘消息：宿主是 WPF `Application`，WinForms 的 `ProcessCmdKey` 依赖 WinForms 消息循环的预处理，在 WPF 泵下一次都不会被调用（已实测 `ProcessCmdKey=0`、`WndProc=1`），这正是首版录制完全无响应的原因。修饰键状态改由 `GetKeyState` 实时查询，因为 `WM_KEYDOWN` 的 wParam 只带虚拟键码。
- 仅按修饰键、`Backspace`/`Delete` 与不受支持的按键都保留录制状态并给出可理解提示，不会产生空热键；`Esc` 或失焦恢复进入录制前的组合。
- 新增 `HotkeyGesture` 作为解析、规范化与录制的唯一入口，`GlobalHotkeyWindow` 复用同一套规则，杜绝「录得进去却注册不了」；保存时仍走 `GlobalHotkeyWindow` 校验与重新注册，失败则保留旧热键。
- 录制期间宿主临时注销全局热键，否则录制正在生效的组合会被系统直接派发给截图流程；录制结束立即恢复，恢复失败以托盘提示告知。
- 自测新增组合规范化与拒绝规则、实时回显、录制交互（修饰键、Backspace、Esc 与注销/恢复次数）以及三个设置页的可缩放布局断言；另在 WPF 泵下驱动真实设置窗验证「点击/Enter 进入录制 → 回显 → 完成录制」全链路。2026-08-11 通过 `scripts/dev.ps1 build` 与 `scripts/dev.ps1 test`。

### R3 本轮实现记录

- 翻译设置页新增多行「翻译提示词」编辑区，始终显示完整内置默认值并保存到 `prompts.translate`；重新打开设置会从配置恢复。点击「恢复内置默认」会重新填入可继续编辑的完整提示词，不再把默认内容隐藏在代码里。
- 自定义翻译提示词会在请求发送前仅替换 `{{target_language}}`；未知占位符保持原样，避免静默改变主人自定义的语义。视觉一条龙在用户提示词后额外附加稳定的流式分栏协议，保证自定义文案不会破坏 OCR 原文/译文分流。
- 通用页的目标语言改为自然语言下拉选择（如「中文（简体）」「俄语」），不再要求主人记忆 `zh-CN` 等代码；读取旧配置时仍兼容既有语言代码，保存后统一为自然语言名称。
- 文本与视觉内置翻译提示词均明确要求输出当前目标语言的译文；文本翻译额外明确禁止解释、注释和原文，减少模型凭猜测改用其他语言的概率。
- 已补充默认中文目标、自定义占位符展开与视觉流式协议的自测，并于 2026-08-10 通过 `scripts/dev.ps1 build` 和 `scripts/dev.ps1 test`。真实端点的中译验收仍需主人在真机使用有效 API Key 完成，测试过程不得打印或落盘密钥。

### 本次代码审阅补充的问题

1. **重译会把新译文追加到旧译文后。** `OnTranslateClick` 直接发起新的流，但 `StartTranslationAsync` 在开始前没有清空 `TranslationTextBox`；这会让用户无法判断哪段是当前结果。该问题与 R1/R2 一起整改。
2. **结果卡位置没有利用选区坐标。** 当前选区坐标未传给结果卡，且卡片居中显示；这不符合 Vision 中「紧贴选区下方，空间不足翻到上方」的既定体验。
3. **通用页的 pipeline mode 控件没有加入选项或视图。** `GeneralPage` 创建了 `_pipelineMode`，但没有填充选项也没有添加到界面；点击保存会回退为 `local_ocr`。即使本轮不重点扩展图像一条龙，也必须避免设置页面静默改变它。
4. **配置档复制不应默认复制 API Key。** API Key 是 DPAPI 机密，复制配置档时应只复制非敏感连接参数，并在 UI 中明确提示新档需要单独设置密钥。
5. **阶段 3 的已有自测没有覆盖上述 UI 与数据完整性回归。** 新实现必须至少补齐配置档切换、配置档显示名、版本保留、重译清空、结果卡生命周期和热键录制的自动化或可重复手工验收。

## 目标交互与 UI 规格

图示状态：**目标**。颜色、图标库和精确像素可在实现时细化，但以下信息关系、层级和状态为稳定约束。

```text
                         已冻结画面
                 ┌─────────────────────┐
                 │       选区          │
                 └─────────────────────┘
                           │ 优先下方；无空间则上方
                           ▼
┌────────────────── 结果卡（普通窗口之上，不主动抢焦点）─────────────────┐
│ 原文（可编辑）                                      [复制] [翻译/重新翻译] │
│ ┌────────────────────────────────────────────────────────────────────┐ │
│ │ OCR 原文；点击输入区后卡片获得焦点，允许键盘编辑。                 │ │
│ └────────────────────────────────────────────────────────────────────┘ │
│ ────────────────────────────────────────────────────────────────────── │
│ 译文                                                [复制] [设置]          │
│ ┌────────────────────────────────────────────────────────────────────┐ │
│ │ 仅显示本次翻译的流式文本；每次翻译开始先清空上一份译文。           │ │
│ └────────────────────────────────────────────────────────────────────┘ │
│ 状态：OCR 完成 / 正在连接 / 正在翻译 / 翻译完成 / 可读错误说明       │
└───────────────────────────────────────────────────────────────────────┘
```

### 结果卡约束

- **层级与摆位：** 对正常桌面窗口保持置顶，优先放在选区下方；下方空间不足时放在上方；最终位置必须被工作区夹取，不能落出屏幕。独占全屏与受 DRM 保护内容仍是产品已知平台边界，不以 `Topmost` 承诺突破。
- **焦点策略：** 新结果出现、流式追加、设置窗口打开均不得抢走前台应用焦点。用户点击原文输入区或明确点击编辑动作时，结果卡必须获得焦点并将插入点放入原文框；编辑完成后允许继续使用翻译按钮。不能再用永久 `WS_EX_NOACTIVATE` 阻断编辑。
- **按钮层级：** 「翻译」是主要操作，使用统一的强调按钮；「复制」「设置」是次要操作，使用较弱的图标加文字或清晰文字按钮。所有按钮需要一致的高度、内边距、悬停、禁用和焦点状态，不能依赖系统默认的裸按钮外观。
- **译文状态：** 初始为空时显示「翻译」；已得到一次结果后显示「重新翻译」。发起任意一次翻译前清空旧译文和状态，再开始流式输出；取消或失败不得伪装成成功。
- **生命周期：** 设置窗没有资格关闭结果卡。结果卡只在用户关闭、应用退出或新选区替换其内容时改变生命周期；关闭结果卡才取消它所关联的翻译请求。

### 设置页布局与可操作性

- 翻译页改用随容器伸缩的两列表格或等价布局：标签列固定，输入列填满；仅 Base URL、模型、API Key 等右侧无功能按钮的控件必须尽量利用整行宽度。
- 设置窗底栏与「保存」「取消」均使用显式最小高度（建议不小于 32 逻辑像素）和足够上下内边距；在 100%、150%、200% 缩放下文字都不得裁切。
- 「关于」页展示 `NaniKore`、产品版本、配置文件路径，以及现有的隐私说明；版本为只读信息。

## 配置契约

### 根配置、运行时副本与机密边界

1. 仓库根目录提供并跟踪 `config.yaml`，作为开发、构建与发布的**非敏感配置模板**；其中绝不写 API Key、私钥或机器专属路径。
2. 项目文件将它作为内容复制到 Debug 输出目录和发布输出目录；程序继续从运行目录（`AppContext.BaseDirectory`）读取和保存副本，因此发布版可携带相邻配置文件。
3. Debug/发布复制使用「源文件较新时刷新」的语义；设置页保存不会回写项目根目录。开发者要修改默认配置时编辑根文件，运行时临时调整仍在输出目录完成。
4. API Key 继续只由当前 Windows 用户的 DPAPI 存储保存。根配置和发布目录可安全审阅、提交或打包。

### 产品版本与配置 schema 版本

现有整数 `version` 被用于配置迁移，和主人要求的发布版本不是同一个概念。为避免保存设置时改变版本或破坏迁移，配置升级为：

```yaml
# 仅由主人手工维护；应用不得自动递增、推导或覆盖。
version: 0.1.0+0

# 仅供程序读取旧配置和执行迁移；不展示为产品版本。
schema_version: 1

general:
  auto_translate: false
  target_language: zh-CN

pipeline:
  mode: local_ocr
  active_profile: openai-default

profiles:
  - id: openai-default       # 稳定技术标识，用于 active_profile 和 DPAPI 密钥索引
    name: 默认 OpenAI 配置档 # 可由用户重命名的显示名
    kind: openai
    api_type: completions
    base_url: https://api.openai.com/v1
    model: gpt-4o-mini
    supports_vision: false
    timeout_seconds: 60

prompts:
  # 可留空以使用内置默认；自定义时支持 {{target_language}} 占位符。
  translate: ''
  explain: ''
```

兼容要求：读取旧的 `version: 1` 配置时，必须识别为旧 schema，而非把它展示成产品版本 `1`；迁移后的保存不得自动修改手工产品版本。关于页始终读取并原样显示 `version`。

### 配置档与提示词编辑规则

- 每个 profile 使用不可随显示名改变的 `id`；下拉列表显示 `name`。新增 profile 生成稳定 `id` 和可编辑的默认名称。
- 配置档切换前先把当前输入框提交到**离开的** profile，之后再加载新 profile；选择事件不得把 A 的编辑值写进 B。
- 重命名仅改 `name`，因此 `active_profile` 与 DPAPI 密钥仍指向同一个 `id`。如果将来确有技术 `id` 重命名入口，必须显式迁移/删除旧 DPAPI 机密并给出确认提示，不能静默丢失。
- 删除 profile 时维持现有的二次确认与机密删除；复制 profile 不复制 API Key。
- 翻译页新增「翻译提示词」多行编辑区，始终展示完整的内置默认提示词并保存到 `prompts.translate`；提供「恢复内置默认」操作和 `{{target_language}}` 使用说明。旧配置中的空提示词仍回退为同一内置默认值。
- 内置默认提示词必须清楚要求「把输入翻译为 `{{target_language}}，只返回译文」，而不是依赖模型猜测语言。自定义提示词在发送前替换 `{{target_language}}`；未知占位符不应被静默吞掉。
- 「测试连接」只验证端点可返回内容，不能当作翻译质量验收；另设真实中文目标的翻译回归。

## 热键录制规格

热键页不再暴露可随意编辑的字符串输入框。采用只读显示框加「录制」按钮（或点击显示框进入录制）的受控交互：

1. 进入录制后显示「请按下快捷键，Esc 取消」。
2. 捕获 `Ctrl`、`Shift`、`Alt`、`Win` 与一个普通键，实时显示标准化组合，例如 `Ctrl+Shift+Q`。
3. 必须至少含一个修饰键和一个当前全局热键实现支持的普通键；只按修饰键、重复按键或不支持按键时保留录制状态并给出可理解提示。
4. `Esc`/取消恢复原值；`Backspace` 不能产生空热键。
5. 保存时仍调用统一的 `GlobalHotkeyWindow` 校验并尝试重新注册；若被其他程序占用，保留旧注册热键、显示失败原因且不写入配置。

## 实施顺序

1. **P0 数据与主旅程护栏：** 修复配置档切换写错对象、定义 `id/name`、补迁移与数据完整性测试；再修复结果卡编辑激活、层级、重译清空和设置关闭生命周期。
2. **P0 翻译可靠性：** 提示词 UI、占位符解析、默认中文目标回归与真实 endpoint 验收。排查 profile 覆盖修复后实际生效的 provider、模型、目标语言与提示词。
3. **P1 配置发布与版本：** 根 `config.yaml` 模板、构建/发布复制规则、产品版本在关于页展示。
4. **P1 设置完成度：** 热键录制、按钮高 DPI 修复、配置页动态布局。
5. **P2 视觉收口：** 统一结果卡操作样式、复制反馈、空/加载/失败状态和文案微调。

每一批保持 `scripts/dev.ps1 build` 与 `scripts/dev.ps1 test` 通过；涉及真实 API 的检查不得把 API Key 打印、写入 Git 或加入测试夹具。

## 验收标准

### 自动化或可重复验证

- 根 `config.yaml` 在 Debug 构建和 `scripts/dev.ps1 publish` 后均存在于运行目录；产物内没有 API Key。
- 启动读取根配置模板时不再因 `version: x.y.z+b` 触发 YAML 反序列化失败，且 `version` 原样保留。
- 保存设置、重启进程后，`version: x.y.z+b` 原样保留；关于页显示同一字符串；程序不自动递增版本，也不要求或展示 Schema 版本。
- [x] 配置档 A 修改 Base URL/模型后切换到 B，B 的字段和 A 不相互覆盖；切回 A 能看到自己的修改。重命名 A 后，A 仍可被设为活动档并读取原有 DPAPI 密钥。
- 翻译提示词能保存、重启后恢复；空提示词走内置默认；`{{target_language}}` 在请求前被替换为当前目标语言。
- 发起第二次翻译时，旧译文会清空，结果区只显示第二次流的内容。
- 设置窗关闭后结果卡仍可见，关闭设置不取消仍在进行的翻译；设置窗从结果卡打开时保持置顶，不被已有普通窗口遮挡；关闭结果卡才取消相关请求。
- 热键录制能输出规范化组合；非法组合和已占用热键不会覆盖正在生效的热键。

### 主人真机验收

- 通过截图 OCR 得到结果卡后，卡片在普通应用窗口上方显示，并优先贴在选区附近；没有空间时自动翻到选区上方。
- 结果出现时当前游戏、视频或文档窗口不失焦；点击原文后可输入、选中、粘贴、修改，再点击「翻译/重新翻译」可得到新译文。
- 在 `target_language: zh-CN` 下，以至少一段英文和一段日文 OCR 文本翻译，输出为中文且无无关法语；更换自定义提示词后效果可由用户控制。
- 翻译页在 100%、150%、200% 显示缩放下，Base URL、模型等输入框宽度合理；保存/取消文字完整可见。
- 从结果卡点「设置」并保存或取消后，结果卡不会关闭或被遮挡；返回原文编辑、重译均正常。

## 风险与待核对项

- `Topmost` 能解决普通桌面窗口遮挡，但不能绕过独占全屏、DRM 画面或其他更高特权窗口；验收需明确区分这些平台边界。
- 「不抢焦点」与「可编辑」存在天然张力，实现必须以用户的显式编辑点击作为切换点，并在真机上验证 WinForms/WPF 混合窗口的焦点行为。
- 外部模型是否稳定遵守中文目标不仅受 prompt 影响，也受模型、兼容端点及 profile 实际配置影响；修复 R6 后应先确认真实请求使用的是预期 profile，再判断模型质量。
- 当前仍处于早期开发阶段，不兼容已废弃的旧配置布局；未来格式稳定且确有迁移成本时，再单独设计迁移方案。
