# [快改] 修复结果面板滚动条常驻与底部统计条被裁

> **读者：** 以后搜到这条时——「改了啥、怎么信、动没动制度记忆」。  
> **自检（四答即可，可合成短段，勿空标题凑节）：** 做了什么 · 改了哪些文件 · 怎么验证 · 对 `codestable/` 有无影响。

主人反馈：结果面板默认状态下不需要滚动条，底部时长统计（Token/TTFT/生成速度指标条）应完整显示；且放大窗口后底部依旧分不到空间，余量全被原文/译文区吞走。

根因是内外边距职责混用：内容 `Grid` 自己挂 `Margin="16,14,16,14"`，同时 `MinHeight` 绑 `ContentScrollViewer.ViewportHeight`。ScrollViewer 的 extent 会把子的 Margin 一并计入，而 MinHeight 只等于视口高度——于是 extent 恒等于「视口 + 纵向 Margin（28px）」，**任何窗口尺寸下都永久溢出 28px**：滚动条常驻、底部指标条永远被裁约 15px，放大窗口也治不好（星号行吞掉所有余量，底部照样在折叠线以下）。无头探针实测：修复前 700×443 与 1600×860 两种视口下 `extentH = viewportH + 28`、`ScrollableHeight = 28`、指标条底边超出视口。

修法是一行边距归属变更：纵向（及横向）内边距全部上移到 `ScrollViewer.Padding="16,14,16,14"`，内容 Grid 不再挂 Margin。ViewportHeight 本身已扣除 Padding，`extent == viewport` 精确成立，内容不高时零滚动条；内容真高（长译文、展开精讲）时滚动条按 issue 015 的两级滚动设计照常出现。视觉间距与改动前完全一致（同一 16/14 内边距，只是承载元素不同）。

- 改动：`src/NaniKore/App/ResultPanelWindow.xaml` — `ContentScrollViewer` 增 `Padding="16,14,16,14"`；内容 Grid 移除 `Margin`；注释补记「边距必须与 MinHeight 绑定分离」的原因与失效模式。
- 改动：`src/NaniKore/Diagnostics/SelfTest.Ui.ResultPanel.cs` — 新增 `TestResultPanelViewportLayout`：默认（700×443）与放大（1600×860）视口下零滚动条、`ScrollableHeight == 0`、指标条底边不超视口；结构不变量（内边距在 ScrollViewer.Padding、Grid 无纵向 Margin）；反向契约（展开精讲内容真高时外层滚动条仍按设计出现）。附无头测量辅助 `ArrangePanelViewport`（直接对 ScrollViewer 子树 Measure/Arrange，不 Show 窗口，不依赖真实桌面会话）。
- 改动：`src/NaniKore/Diagnostics/SelfTest.Ui.cs` — 调度注册新测试。
- 验证：`dev.ps1 build` 0 警告 0 错误；`dev.ps1 test` 全绿（613 PASS / 0 FAIL，新增 5 条布局断言全过）。修复前同一探针输出 `extentH=471.2 / viewportH=443.2 / scrollableH=28`，修复后 `extentH=415.2 / viewportH=415.2 / scrollableH=0`。
- codestable：无影响（issue 015 的「整页滚动 + 精讲局部滚两级滚动」设计原样保留，只是补掉了 margin 溢出这个常驻滚动条缺陷；spec 未记录具体边距数值，无口径失效）。
