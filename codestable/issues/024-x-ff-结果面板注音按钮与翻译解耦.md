# [快改] 结果面板补「注音」按钮，注音与翻译彻底解耦

> **读者：** 以后搜到这条时——「改了啥、怎么信、动没动制度记忆」。  
> **自检（四答即可，可合成短段，勿空标题凑节）：** 做了什么 · 改了哪些文件 · 怎么验证 · 对 `codestable/` 有无影响。

---

主人反馈：结果面板需要一个「注音」按钮，放在「规范化」右侧、「翻译」左侧；对原文区的文本标注读音不应该非得点翻译按钮才开始（未开自动翻译时，原文区停在纯文本编辑态，只有点翻译或点开焦点才看得到假名阅读态）。

按钮语义 = 「立即按当前源语言口径把读音叠到原文区并展示假名阅读态」，复用 issue 008 Phase 3 既有的单次异步注音链路，不新增引擎逻辑：编辑态先经 `CommitEditingSourceIfActive` 提交为事实源（假名只能由 FlowDocument 承载，编辑框里只看得到纯文本），再走 `AnnotateSourceAsync(manual: true)` 强制重算——手动触发即便纯文本未变也按当前下拉语言重新叠加。空原文温和提示「没有可注音的原文。」；总开关关闭/词典缺失走 `RunAnnotationAsync` 既有 manual 软降级文案，不抛错不清原文。按钮随 `SetTranslationInProgress` 与规范化/翻译同步禁用，`Reset` 同步复位。

- 改动：`src/NaniKore/App/ResultPanelWindow.xaml` — 工具栏在「规范化」与「翻译」之间新增 `AnnotateSourceButton`（「注音」，ToolTip 说明无需先翻译）。
- 改动：`src/NaniKore/App/ResultPanelWindow.xaml.cs` — 新增 `OnAnnotateSourceClick`（提交事实源 + 空文案提示 + manual 重注）；`Reset` 复位按钮启用态；`SetTranslationInProgress` 同步禁用。
- 改动：`src/NaniKore/Diagnostics/SelfTest.Ui.ResultPanel.cs` — 新增 `TestResultPanelAnnotateButton`：工具栏顺序契约（规范化 → 注音 → 翻译）、编辑态点击即切假名阅读态且不发起翻译、ja 词典就绪时假名叠加且纯文本事实源不变（未就绪 SKIP）、空原文提示、开关关闭软降级。
- 改动：`src/NaniKore/Diagnostics/SelfTest.Ui.cs` — 调度注册新测试。
- 改动：`README.md` — 功能列表补「原文区本地注音 + 注音按钮」说明。
- 验证：`dev.ps1 build` 0 警告 0 错误；`dev.ps1 test` 全绿（613 PASS / 0 FAIL，新增 6 条断言全过）。
- codestable：无影响（spec 未逐一列举结果面板工具栏按钮，无既定口径失效；注音引擎、源语言下拉、双模切换等既有真相原样不变）。
