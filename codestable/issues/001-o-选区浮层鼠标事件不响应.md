# 选区浮层鼠标事件不响应

## 问题描述

使用 Gio v0.10.1 创建的全屏选区浮层窗口无法接收鼠标事件。

**预期行为：**
- 用户按下 Ctrl+Shift+A 后看到半透明黑色蒙层
- 可以拖动鼠标框选区域
- 选区显示白色边框和尺寸信息
- 松开鼠标完成选择

**实际行为：**
- 窗口显示为灰色不透明（不是预期的半透明黑色）
- 鼠标点击和拖动完全无响应
- 日志中没有 "Pointer event" 输出
- 窗口事件循环正常（收到 FrameEvent, ConfigEvent 等）

## 复现步骤

1. 编译并运行 nanikore.exe
2. 按 Ctrl+Shift+A 触发屏幕捕获
3. 全屏灰色窗口出现
4. 尝试点击或拖动鼠标 → 无响应

## 相关代码

`pkg/overlay/selection.go`:
- Line 88-124: `layout()` 方法的事件处理
- Line 164-189: `handlePointer()` 方法

## 日志输出

```
23:07:44 selection.go:50: Selection overlay window created, starting event loop...
23:07:44 selection.go:67: Selection overlay event loop started
# 之后只有 FrameEvent 和 ConfigEvent，没有 pointer.Event
```

## 已尝试的方案

1. **使用 `pointer.Filter` + `gtx.Event()` API**
   ```go
   for {
       ev, ok := gtx.Event(pointer.Filter{
           Target: o,
           Kinds:  pointer.Press | pointer.Drag | pointer.Release,
       })
       ...
   }
   ```
   结果：无效

2. **使用 `clip.Rect.Push()` 创建输入区域**
   ```go
   stack := clip.Rect{Max: gtx.Constraints.Max}.Push(gtx.Ops)
   // 处理事件
   stack.Pop()
   ```
   结果：无效

3. **添加 `pointer.Move` 事件类型**
   ```go
   Kinds: pointer.Press | pointer.Drag | pointer.Release | pointer.Move
   ```
   结果：无效

## 可能的原因

1. **Gio 全屏模式的已知问题**
   - v0.10.1 可能在 Windows 全屏模式下事件路由有 bug
   - 社区反馈需要验证

2. **事件注册方式不正确**
   - Gio 的 API 在不同版本间变化较大
   - 当前使用的方式可能不适用于 v0.10.1

3. **全屏窗口需要特殊处理**
   - Windows 全屏独占模式可能拦截输入
   - 需要使用分层窗口（layered window）

4. **绘制顺序问题**
   - 蒙层绘制可能在事件区域之后，导致事件被遮挡

## 待验证方案

### 方案 A：修改 Gio 实现

1. **降级 Gio 版本**
   - 尝试 v0.7.1（go.mod 中原计划使用的版本）
   - 验证早期 API 是否更稳定

2. **升级到最新版本**
   - 尝试最新的 Gio 版本
   - 可能已修复相关 bug

3. **改用窗口化模式**
   ```go
   o.window.Option(
       app.Size(unit.Dp(screenWidth), unit.Dp(screenHeight)),
       app.Maximized.Option(),
       app.Decorated(false),
   )
   ```
   - 不使用 `Fullscreen.Option()`
   - 用最大化窗口替代全屏

4. **研究 Gio 官方示例**
   - 查找处理全屏输入的示例代码
   - 参考 Gio 社区的实现

### 方案 B：切换技术栈

1. **使用 WebView2**
   - 库：`github.com/jchv/go-webview2` 或类似
   - HTML Canvas 绘制选区界面
   - JavaScript 处理鼠标事件
   - 优点：成熟、文档丰富、事件处理直接
   - 缺点：需要 WebView2 runtime 依赖（Win11 预装，Win10 需安装）

2. **使用原生 Win32 API**
   - 直接调用 `user32.dll` 创建分层窗口
   - `SetLayeredWindowAttributes` 设置透明度
   - `WM_MOUSEMOVE`, `WM_LBUTTONDOWN` 等消息处理鼠标
   - 优点：完全控制、无第三方依赖
   - 缺点：代码量大、需要深入 Windows API 知识

3. **使用 Wails v3**
   - 如用户最初提到的备选方案
   - 依赖系统 WebView，体积小
   - 缺点：整个 app 变成 WebView 驱动，可能影响主路径性能

### 方案 C：混合方案

- 主界面（托盘、设置）：Gio
- 选区浮层：WebView2 或 Win32
- 结果卡片：Gio
- 精讲面板：WebView2（已在 vision 中规划）
