# 配置自动迁移与产品版本单一来源

## 背景

当前 `config.template.yaml` 的 `version` 同时承担产品版本号：`scripts/dev.ps1` 从模板读取 ZIP 版本，Debug 构建递增该字段，`AppConfig.Version` 再把它写入用户配置。已有用户配置不会随模板更新；关于页发现 major/minor 不同后只提示用户手动对照模板。用户可能不会手动改配置，也无法可靠判断该改什么。

配置结构演进应由应用自动完成，而不是让用户复制模板或手改配置。产品版本也不应依赖一份随包 YAML 模板单独维护。本项承接 [047 R11](047-o-first-public-release-hardening.md#r11readme-先帮助普通用户成功使用)，只规划，不代表迁移已实现。

## 目标

- 用户升级后，应用自动把受支持的旧配置迁移到当前结构，保留用户设置。
- 产品版本只有一个开发者维护的来源，不再存在模板版本、用户配置版本与程序集版本之间的漂移。
- 迁移失败、配置损坏、未知未来 schema 或写盘失败时，原始 `config.yaml` 保持不变，符合 R09 的拒绝覆盖策略。
- 迁移仅处理 `.data/config.yaml`；不改写密钥、收藏数据库、模型或注音数据。

## 方案边界

- 产品版本由项目构建元数据作为唯一来源，发布归档名、About 页和诊断输出都读取同一版本；移除模板中的产品版本字段及用户配置中的产品版本职责，停止通过递增 `config.template.yaml` 管理版本。
- 配置结构单独使用应用管理的 `schema_version`。固定的初始基线为 `0`：随包模板只写一次 `schema_version: 0`，不随每次迁移改成最新版本；未标记的当前已支持布局也按基线 `0` 处理，不因此接受任意早期格式。应用代码按显式、顺序、确定性的 `N -> N+1` 步骤迁移，不用产品版本推断配置结构。新增可省略字段可直接使用代码默认值，不强制动已有文件。
- 首启仍按字节复制随包模板；迁移器读取基线 `0` 并自动写出当前 schema，用户不需要编辑模板或配置。已是当前 schema 的配置启动时不写盘。
- 在忽略未知键的类型化反序列化之前检查结构，避免先丢失待迁移字段。每一步只修改登记字段，保留显式值与未涉及内容；未知键若无法无损保留，则拒绝自动迁移，不静默丢弃。
- 先读取并在内存中执行全部步骤，严格校验目标配置；提交前保留一份逐字节备份，确认源文件未被其他写入修改，再用同目录临时文件原子替换。解析、校验或提交失败时保留原配置，提示出错原因与恢复方式，并阻止普通保存覆盖原件。不能识别的历史格式、不支持的未来 schema 都不得猜测或降级重写。
- 普通设置保存继续走 `ConfigStore.AtomicWrite`；迁移与其共用底层原子写入，不把旧结构交给普通保存，也不另建一套序列化机制。

## 实施步骤

1. 盘点当前正式模板、已知历史配置形态、版本展示和构建脚本的版本读写点；确定首次发布的 schema 基线与不支持的历史格式处理口径。
2. 将产品版本收敛到项目构建元数据，调整 Debug 版本递增与 ZIP 命名；移除产品版本对模板和用户配置的依赖，并同步 README、Project Spec 和 About 页。
3. 为磁盘配置增加应用管理的 schema 标记与迁移入口；将迁移步骤实现为纯、可测试的文档转换，全部成功后再验证并原子保存。
4. 对读取失败、历史格式、未来 schema、迁移中断、临时写入失败和重启重复运行建立隔离目录回归测试；证明失败路径逐字节保留原文件，成功路径完整保留用户设置。
5. 在全量自测通过后验证 Debug 与 Native AOT 的首启、升级、重启和发布包路径；更新 047 R11/R09 的证据及本 Issue 状态。

## 验收条件

- 新安装、旧 schema 升级、重复启动三种路径最终得到当前 schema，用户无须编辑配置或模板。
- 已支持字段、提示词、配置档、热键、窗口设置和显式关闭的开关均按迁移契约保留；迁移不会重置未涉及字段。
- 格式损坏、未知未来 schema、未登记历史格式或任一写入阶段失败时，旧配置字节不变，并给出明确恢复提示；成功后再次启动不重复迁移、不再写盘。
- 发布版本号只在一个项目构建元数据来源维护；构建、About 页、诊断输出、ZIP 文件名一致，不再依赖 `config.template.yaml` 中的产品版本。
- `./scripts/dev.ps1 test`、Debug 构建和 Native AOT 发布验证通过；专项测试覆盖每一条迁移和失败边界。

## 非目标

- 不自动迁移 DPAPI 密钥、收藏数据库或 `deps/` 内容。
- 不猜测或兼容未登记的任意旧字段，不提供模板与用户配置的双向同步。
- 不在迁移失败时自动重置配置，也不将产品版本变化当作配置 schema 变化。
