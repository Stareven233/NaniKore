# 界面与提示词字体可配置化

> **读者：** 接手实现的人——「为什么要动字体、现在有哪几处决策点、配置契约怎么定、哪些口径已经拍死、哪些是穿刺风险」。
> **来源：** 主人反馈「另一台 Win11 上字体显示效果不同」，追查后确认根因是 Avalonia 不内置字体、回退链里的 `更纱黑体 / Sarasa / PingFang` 并非 Windows 自带，
> 且链尾 `sans-serif` 在 Avalonia 中不是有效通用族名（等于失效）。**不采用内嵌字体包**（体积代价不可接受），改为让字体族成为用户可配置项。
> **设计演进：** 首版曾计划自绘字体选择弹窗，后经主人复核否决——弹窗为一个「选字符串」造了完整窗口生命周期与 3 条专属自测，不抵其价值。现版改用内置 `AutoCompleteBox`，零新窗口、零新文件。

---

## 做成以后是什么样

- `config.yaml` 里有 `fonts.ui` 与 `fonts.prompt` 两个字体族键；`config.template.yaml` 直接写明默认值，**代码里不再存在任何字体族回退链常量**。
- 设置页「通用」新增两个字体设置行：输入框本身即搜索框，键入时从**本机已安装字体**里补全下拉，同时接受任意手填族名。
- 保存后界面字体立即热刷新（不重启），重启后按配置持久生效。
- 换一台 Windows 机器，只要用户没有改过配置，观感由模板里的默认值决定，不再受那台机器字体表里装了什么影响。
- 字体键留空是**合法状态**，等价于交给 Avalonia 平台默认字体，不回落任何内置值。

**范围：** 包含 `fonts` 配置段、`Font.Ui` / `Font.Prompt` 两个资源键的运行期注入、设置页两行 + `AutoCompleteBox` 输入控件、`SelectionOverlayWindow` 的 `Typeface.Default` 收敛、`Font.Mono` 死键清理。
**不包含：** 内嵌字体文件（明确否决）、图标字体（`Segoe Fluent Icons` 属字形表，不对外开放）、结果面板正文与注音的字号体系（只换族，不动字号与行高）、`scripts/prompt-preview.html`（开发期预览页，另行处理）。

**归属：** 根 `issues/` 的独立 Issue。这是**全新产品特性**（字体可配置能力本身），不是 Epic 002「Avalonia 迁移」的尾巴——迁移早已关闭该口径，今天代码里那套硬编码字体链是旧版遗留，本次是对它的能力升级，与 Epic 边界无关。

## 为什么现在做 / 当前坏在哪

主人两台 Windows 机器（一台 Win10 22H2 19045、一台 Win11）显示同一份 UI 字体差异明显。读代码后确认这不是渲染 bug，而是**字体决策全部硬编码在代码里、且依赖本机字体表**：

| # | 位置 | 现在 | 谁在吃 |
|---|---|---|---|
| 1 | `App.axaml:13` `Font.Ui` | `Microsoft YaHei UI, Microsoft YaHei, Segoe UI Variable Text, Segoe UI, 更纱黑体 SC, Sarasa Gothic SC, PingFang SC, sans-serif` | `NaniKoreStyles.axaml` 12 处 Setter，覆盖 `Window/TextBlock/Label/Button/ToggleButton/ComboBox/TextBox/ListBoxItem/...` |
| 2 | `App.axaml:14` `Font.Mono` | `Cascadia Mono, Consolas, Segoe UI Mono, 更纱黑体 SC, Sarasa Term SC, monospace` | **零引用**（死键） |
| 3 | `App/Theme/NaniKoreStyles.axaml` 12 处 | `{DynamicResource Font.Ui}` | 真实生效路径 |
| 4 | `TranslationPage.axaml:132 / :149` | 硬编码 `Cascadia Mono, Consolas, Monaco, 微软雅黑` | 两个提示词编辑框，绕过 `Font.Mono` 自成一套 |
| 5 | `Overlay/SelectionOverlayWindow.axaml.cs:155` | `Typeface.Default` | 选区浮层「宽 × 高」尺寸 chip，落到 `FontManagerOptions.DefaultFamilyName`，完全不受配置控制 |

差异被放大的三个具体原因：

1. `更纱黑体 SC / Sarasa Gothic SC / PingFang SC` **都不是 Windows 自带**。本机装了 user-font 版 sarasa，另一台大概率没有 → 链尾落空行为不同。
2. `sans-serif` 在 Avalonia 不是有效通用族名，链尾这一项等于失效，没有真正的兜底。
3. 本机是 Win10，`Segoe UI Variable Text` 根本不存在（Win11 才有）；一旦雅黑没命中，Win11 会掉到 Variable Text、Win10 直接跳 Segoe UI，中文字形与字重换脸。

**主人的裁决（2026-11-08 两轮对话已确认，均已定稿）：**

| # | 裁决 |
|---|---|
| C1 | **不内嵌字体**：体积代价不可接受，改为运行期配置。 |
| C2 | **字体键留空允许保留**：空串 = 不写资源 = Avalonia 平台默认字体，**不回落任何代码内默认值**。这样代码里零字体族常量。（候选 (a)） |
| C3 | **模板默认值走手测拍定值**：`ui: Microsoft YaHei UI`（单值）；`prompt: 'YaHei Monaco Hybird,Consolas'`（回退链，2026-11-08 主人在真实界面手测后拍定，覆盖首版「prompt 写单值 Consolas」）。 |
| C4 | **默认值必须保证任何 Windows 都能渲染**：雅黑与 Consolas 自 Vista 起随所有语言版附带；`Cascadia Mono` 只有 Win11 附带，不得做默认。prompt 的回退链以 `Consolas` 收尾满足该约束。 |
| C5 | **不做浮层独立槽位**：只保留「界面字体」+「提示词字体」两块。 |
| C6 | **不做独立预览区**：不设专门的示例文本控件；预览能力由输入框内的文字自己承担——输入框以当前填的字体族渲染自己（零额外控件、零额外布局）。 |
| C7 | **字体输入用 `AutoCompleteBox`，不自绘对话框**：输入框即搜索框，键入时补全下拉（`FilterMode=Contains`），同时接受任意手填族名与逗号回退链。详见「4. 字体输入控件」。 |
| C8 | **不为老配置开兼容**：不写迁移代码、不读旧资源键。 |
| C9 | 顺手清理 `Font.Mono` 死键与 `TranslationPage` 的重复硬编码链。 |
| C10 | **零新窗口、零新控件类**：不新增任何 `.axaml`/`.cs` 文件，只复用 Avalonia 内置控件与既有隐式样式。 |

## 现状怎么工作

```text
App.axaml 静态资源 Font.Ui / Font.Mono
    └─ NaniKoreStyles.axaml 隐式样式（{DynamicResource}）
         └─ 全部 Avalonia 控件
TranslationPage.axaml 自己写死一条等宽链（不经资源）
SelectionOverlayWindow.axaml.cs 直接用 Typeface.Default（不经资源）
```

一句话：**字体族是编译期常量，运行期没有任何写入口。**

## 目标配置契约

```yaml
fonts:
  # 界面字体族名，随包默认 Microsoft YaHei UI（所有 Windows 语言版自带）。
  # 可填任意已安装字体族名；用英文逗号分隔即构成回退链（如 "Microsoft YaHei UI, Segoe UI"）。
  # 留空 = 使用 Avalonia 平台默认字体（不做任何内置回落）。
  ui: Microsoft YaHei UI
  # 提示词编辑框等宽字体族名，随包默认一条回退链：本机装了 YaHei Monaco Hybrid 就用它，否则落链尾 Consolas。
  prompt: 'YaHei Monaco Hybird,Consolas'
```

- 键名走 `UnderscoredNamingConvention`，C# 侧为 `FontConfig.Ui` / `FontConfig.Prompt`（`string`，非 null）。
- **两个键都允许为空**（C2）。空值语义只有一条：`FontResources.Apply` 不写对应资源键 → 控件落到 Avalonia 的平台默认字体。
- **模板默认值的选型依据**（C4）：`ui` 取 `Microsoft YaHei UI`（`msyh.ttc`），自 Windows Vista 起随**所有语言版本**的系统附带，不存在「装了才有的字体」。`prompt` 的回退链首项是主人偏好的等宽混合族，链尾 `Consolas`（`consola.ttf`）同样所有 Windows 自带，因此首项未安装的机器仍有确定、可读的等宽兜底。`Cascadia Mono` 只在 Win11/终端附带，**不能**做默认。
- `fonts` 段登记进 `ConfigYamlStaticContext`（`[YamlSerializable(typeof(FontConfig))]`），并挂到 `AppConfigDocument`，语义同 `Phonetics`（非配置档小节，不做缺省省略）。

## 实现安排

### 1. 配置层

| 落点 | 改动 |
|---|---|
| `Config/AppConfig.cs` | 新增 `FontConfig { string Ui; string Prompt; }`，`AppConfig.Fonts` 属性，以及 `AppConfigCloner` 对应克隆 |
| `Config/ConfigDocument.cs` | `AppConfigDocument.Fonts`，`ToRuntime`/`ToDocument` 双向挂接 |
| `Config/ConfigYamlStaticContext.cs` | 登记 `FontConfig`（漏登记会 YDNG001，`TreatWarningsAsErrors` 直接构建失败） |
| `Config/ConfigStore.cs` | `Normalize` 收敛 null → 空串（避免 `OmitNull` 把 `fonts` 段塌成 `{}`，与 `prompts` 段同一处理范式）；**不做任何字体名兜底，空串原样保留**（C2） |
| `config.template.yaml` | 落 `fonts:` 段：`ui` 单值、`prompt` 回退链（主人手测拍定）+ 注释说明「逗号分隔即回退链」「留空 = 平台默认」 |

### 2. 运行期注入（唯一写入口）

新增 `App/Theme/FontResources.cs`：

```csharp
internal static class FontResources
{
    public const string UiKey = "Font.Ui";
    public const string PromptKey = "Font.Prompt";

    // 把配置里的字体族写进 Application.Resources；DynamicResource 自动刷新已存在的控件。
    public static void Apply(FontConfig fonts);
    // 探针：判断族名是否落在本机字体表（用于设置页警告与自渲染预览判定，不改变失败语义）。
    public static bool IsInstalled(string familyName);
    // 本机已安装字体族名快照（去重 + 大小写不敏感排序），惰性枚举一次，两个输入框共享。
    public static IReadOnlyList<string> InstalledFamilies { get; }
    // 尝试构造 FontFamily：空串/非法值返回 null，由调用方回落到平台默认，绝不抛异常。
    public static FontFamily? TryCreate(string? familyList);
}
```

- `Apply` 内部对空串的处理：**跳过该键，不写资源**，不注入任何代码内链（C2）。
- `App.axaml` 删除 `Font.Ui` / `Font.Mono` 两条静态资源定义（C9）；`NaniKoreStyles.axaml` 的键名由 `Font.Mono` 改为 `Font.Prompt`。
  注意一个必须处理的细节：静态资源删掉后 `{DynamicResource Font.Ui}` 在控件构造函数期取不到值不报错（DynamicResource 允许暂缺），这是本方案能成立的前提，也是穿刺风险 1 要验证的点。
  另一处必须同步的地方：`NaniKoreStyles.axaml` 里 `Style Selector="TextBox"` 已经给**所有** `TextBox` 写了 `FontFamily` Setter，而 Style Setter 会压掉继承值——`AutoCompleteBox` 模板内部的 `TextBox` 因此在其中。这意味着字体输入框的预览**光设 `AutoCompleteBox.FontFamily` 无效**，必须直接落到模板内那个 `TextBox` 上（见 4 节）。
- 调用时机：`App.axaml.cs` 的 `InitializeApplication` 中，`_configStore` 建好之后、任何窗口创建之前；`ApplySettings` 里再调一次实现热刷新。
- `Overlay/SelectionOverlayWindow.axaml.cs:155`：`Typeface.Default` → 从 `Font.Ui` 解析出的 `Typeface`（取不到则仍用 `Typeface.Default`）。
- `TranslationPage.axaml:132/149`：硬编码链 → `{DynamicResource Font.Prompt}`。`Font.Mono` 键随之删除。

### 3. 设置页 UI

「通用」页顶部新增一组「外观」卡片（放在现有「常规」组之上，同样用 `SettingsGroup` / `SettingsRow`）：

```text
┌─ 通用 ─────────────────────────────────────────────────────────────┐
│  ┌ 外观 ──────────────────────────────────────────────────────────┐ │
│  │ 界面字体                                                       │ │
│  │ 应用于全部窗口与控件；留空则使用系统默认字体。                 │ │
│  │                    [ Microsoft YaHei UI          ▾ ]           │ │  ← 文本以雅黑自身渲染
│  │ ────────────────────────────────────────────────────────────── │ │
│  │ 提示词字体                                                     │ │
│  │ 提示词编辑框使用的等宽字体；留空则使用系统默认字体。           │ │
│  │                    [ Consolas                    ▾ ]           │ │
│  │ ────────────────────────────────────────────────────────────── │ │
│  │ ⚠ 未在本机找到字体「xxx」                                      │ │
│  └────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

- 两个 `SettingsRow`，右侧 `ContentWidth="320"`，内容为一个占满宽度的 `AutoCompleteBox`。**没有「浏览」按钮、没有弹窗**。
- 说明文字里**不再提「逗号分隔构成回退链」**——那是可选手填能力，写进说明会让默认场景变复杂（C3 精神）；详细写法保留在 `config.template.yaml` 注释里。
- 两个输入框共用组底部**一个** `InfoBar`（`Warn`），点名具体缺失族名，**但允许保存**——用户可以借此写一个只在本机存在的家族。
- 警告在 `TextChanged` 上直接同步刷新（查的是内存里已枚举的列表，不需要异步、不阻塞输入）。
- 保存后立即热刷新：`SettingsWindow` 走既有 `ApplySettings` → `FontResources.Apply(next.Fonts)`，无需重启。

### 4. 字体输入控件（`AutoCompleteBox`）

**不做独立对话框**（C7 已改口径）。原「点浏览 → 弹窗 → 搜索 → 选中 → 确定 → 回填」的六步流程，换成「在输入框里直接打，或点开下拉挑」。

`App/Settings/GeneralPage.axaml`：

```xml
<controls:SettingsRow Header="界面字体"
                      Description="应用于全部窗口与控件；留空则使用系统默认字体。"
                      ContentWidth="320">
    <AutoCompleteBox x:Name="UiFontBox"
                     Width="320"
                     Watermark="留空 = 系统默认字体"
                     MinimumPrefixLength="0"
                     FilterMode="Contains"
                     IsTextCompletionEnabled="False"
                     MaxDropDownHeight="260">
        <!-- 预览字体只作用于输入区；候选固定用界面字体，保证填了任何字体时候选都可读 -->
        <AutoCompleteBox.ItemTemplate>
            <DataTemplate>
                <TextBlock Text="{Binding}" FontFamily="{DynamicResource Font.Ui}" />
            </DataTemplate>
        </AutoCompleteBox.ItemTemplate>
    </AutoCompleteBox>
</controls:SettingsRow>
```

**为什么是它（对照原弹窗）：**

| 维度 | 原自绘弹窗 | `AutoCompleteBox` |
|---|---|---|
| 新增文件 | `FontPickerDialog.axaml` + `.cs` | **0** |
| 新增样式 | 需穿刺验证与主题一致 | **0**——输入区是 `TextBox`、候选是 `ListBoxItem`，两者都已被 `NaniKoreStyles.axaml` 定制 |
| 检索 | 自建过滤 + 空查询显示全部 | `FilterMode="Contains"`（大小写不敏感子串）+ `MinimumPrefixLength="0"`（空查询显示全部） |
| 手填任意字符串 | `TextBox` 与弹窗两套语义 | **一体**：`Text` 就是原始字符串 |
| 手填回退链 `"A, B"` | 弹窗只能返回单族名 | 同样手填，`Text` 原样保存 |
| 键位 / 双击 | 自建回车、Esc、双击 | 控件自带 |
| 返回语义 | `ShowDialog<string?>` 的 null = 取消 | 没有取消，`Text` 即最终值 |
| 自测 | 3 条只守弹窗 | **1 条**（只验证数据源与过滤语义，不管控件外形） |

**取值口径（重要）：** 一律读 `AutoCompleteBox.Text`，**不读 `SelectedItem`**。手填的链式值不会被选中项逻辑吞掉：

```csharp
config.Fonts.Ui = UiFontBox.Text ?? string.Empty;      // 空串合法，语义见 C2
config.Fonts.Prompt = PromptFontBox.Text ?? string.Empty;
```

**候选数据源与懒加载：**

- 唯一数据源 `FontManager.Current.SystemFonts`（本机已安装），取 `Name` 去重排序后缓存进 `FontResources.InstalledFamilies`。
- **挂在 `DropDownOpening` 事件上首次枚举**，不在页面构造 / `Load` 里预取——不点开下拉就零成本，`SelfTest.Ui.Settings` 的「首屏秒开」断言不受影响；两个输入框共用同一份缓存，只枚举一次。
- 同一个 `.ttc` 内多族会以多个名字出现（如 `Microsoft YaHei` / `Microsoft YaHei UI`、`更紗黑體` 一族十几个名），这是字体表真相，不做合并、不做去重猜测。

**自渲染预览（C6）：** 输入框以当前填的字体族渲染**自己**——默认值 `Microsoft YaHei UI` 就在输入框里直接显示雅黑，改成 `Consolas` 立刻变等宽。零额外控件、零额外布局。

```csharp
// 预览直接写模板内 TextBox 的 FontFamily：TextBox 隐式样式的 Setter 会压掉继承值，
// 所以单设 AutoCompleteBox.FontFamily 不会生效。候选列表不受影响（ItemTemplate 已钉回 Font.Ui）。
private static void ApplyPreview(AutoCompleteBox box)
{
    var family = FontResources.TryCreate(box.Text) ?? FontFamily.Default;
    if (box.GetVisualDescendants().OfType<TextBox>().FirstOrDefault() is { } input)
    {
        input.FontFamily = family;
    }
}
```

- 挂在 `TextChanged` 上，两个输入框各自独立；模板未套用时 `FirstOrDefault` 返回 null，静默跳过即可。
- 预览只看输入区：候选列表由 `ItemTemplate` 显式钉回 `Font.Ui`，所以用户把字体填成 `Wingdings` 时，**候选列表仍然可读**。
- 不新增任何「示例文本」控件——预览不是一块区域，就是输入框本身。这就是 C6 从「不预览」放宽到「自渲染」的全部增量。

### 与设计的四处偏差（均有理由）

1. **`Watermark` → `PlaceholderText`**：Avalonia 12 已弃用 `AutoCompleteBox.Watermark`，不改会出 AVLN5001 构建警告。
2. **字体表枚举加了后台预热**：`DropDownOpening` 仍是首取点；额外在 `GeneralPage.Load` 后启动一次 `FontResources.WarmUpAsync`。原因：缺失字体警告的主场景就是「别的机器配的字体本机没有」，只在用户点开下拉后才告警等于失去意义。预热在后台任务，不占首帧；`TextChanged` 仍只查已枚举的内存快照，未就绪时跳过、预热完成回主线程补一次。
3. **自渲染预览的定位方式**：Avalonia 12 的 `AutoCompleteBox.TextBox` 不公开，改用可视树里第一个 `TextBox`，并挂 `TemplateApplied` 补一次——文本赋值可能早于模板套用，否则首次 `Load` 的预览会静默丢失。
4. **未知族名的告警文案说清了保存后的行为**（主人手测后拍定）：探针不改变运行期语义，未安装的族名照样写入资源，渲染由 Avalonia 按平台字体回退处理（视觉上可能仍是别的可用字体）；提示条必须点名这件事，而不是只说「仍可保存」。
