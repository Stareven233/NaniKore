# 选中与剪贴板翻译热键

## 目标

新增第二个全局快捷键 `hotkeys.paste`（默认 `Ctrl+Shift+S`，可录制成 F1–F12 单键）。按下后按优先级取输入：

1. **选区文本**：向前台窗口模拟 Ctrl+C 读取；
2. **剪贴板文本**：模拟无果时用剪贴板里现成的文本；
3. **剪贴板图像**：当前配置档声明 `supports_vision` → PNG 直喂 provider；否则本地 PP-OCRv6 识别成文本；
4. **都没有**：托盘提示。

拿到输入后与截图链路完全同构：同一个 provider、同一套提示词组装、同一个单实例结果面板（振假名、两阶段精讲、收藏、划词气泡、token 指标随行）。此路径无选区矩形，面板以当前鼠标光标位置为锚点，沿用「下方优先、不够翻上方、不抢焦点」与越界钳位。此路径忽略 `auto_translate`，直接开始翻译；`auto_explain` 跟随配置。

## 输入获取流程

```text
按 paste 热键（框选进行中则丢弃本次触发）
   │
   ▼
全量快照剪贴板（Clipboard.GetDataObject → IDataObject）
   │
   ▼
读一次当前剪贴板文本，作为对比基准
   │
   ▼
SendInput 模拟 Ctrl+C → 每 100ms 读一次剪贴板文本，600ms 超时
   │
   ├── 读到非空文本 ──> 来源=选区；剪贴板保持原样（即复制到的原文）
   │
   └── 超时仍无变化 ──> 还原快照；从快照对象取内容：
                 ├── 有文本 ──> 来源=剪贴板文本；剪贴板不动（幂等）
                 └── 有图像 ──> 按能力分流：
                                ├── supports_vision ──> PNG 直喂，剪贴板不动
                                └── 否则 ──> 本地 OCR → 原文写回剪贴板（替换图像）
   │
   ▼
都没有 ──> 托盘提示，结束
```

剪贴板终态规则：只有「模拟 Ctrl+C 自己复制到的」和「本地 OCR 识别出的」两种原文会留在剪贴板里，其余情况原样奉还。还原失败（`ExternalException`）时面板状态栏告知。剪贴板读写与轮询在专用 STA 线程内完成，面板更新回主线程；STA 线程活到操作完成再退出（`OleSetClipboard` 的数据归设置它的单元所有，短命线程退出后可能丢数据，需真机确认）。

## 改动

### 输入与热键

- `Input/HotkeyGesture`：放开 F1–F12 零修饰键，`Parse` / `TryCapture` 同步；F13–F24 仍需修饰键，裸字母数字仍禁；报错文案泛化，去掉写死的「截图」；新增 `IsEnabled`（空串＝不注册）。
- `Input/HotkeySlot.cs`（新增）：`Capture` / `Paste` 槽位枚举与 `HotkeyRecordingState`，录制盒与主程序共用同一份槽位口径。
- `Input/GlobalHotkeyWindow`：构造函数加 id 参数，两个实例用不同 id。代码未拒绝 `modifiers = 0`，卡点只在 `HotkeyGesture`，不为 F 单键加分支。
- `Input/PasteInputAcquirer.cs`（新增）：输入获取状态机、剪贴板网关抽象（`IClipboardGateway` / `ClipboardSnapshot` / `ClipboardPayloads`）、WinForms 真实网关、`SendInputCopySimulator`、专用 STA 线程的 `ClipboardInputSource`、透明铺白与 PNG 编码。
- `Interop/NativeMethods.cs`：补 `SendInput` 与 `INPUT` / `KEYBDINPUT` 结构体及 `KeyboardEvent` 工厂。
- `App/NaniKoreApp`：
  - 托盘创建移到热键注册之前；两个热键各自独立 try/catch，注册失败降级为托盘气泡，互不牵连；
  - 注册 `paste` 热键 → `OnPasteHotkeyPressed` → 输入获取 → 复用 `StartTranslationAsync`；`paste` 为空串时不注册；
  - `OnCaptureHotkeyPressed` 与 `OnPasteHotkeyPressed` 都不再 Close 旧面板，直接 Reset 复用（与托盘「截图翻译」路径对齐）；删除 `_isReplacingResultPanel`；
  - 输入获取加连按守卫，`SelectionForm` 模态期间的 paste 触发丢弃；
  - 新增输入获取组件：模拟 Ctrl+C + 剪贴板快照/还原 + 回落链 + 图像分流；
  - `_lastImagePng`：vision 直喂置为本次 PNG，文本路径置 null（保证面板「翻译」按钮可用）；
  - 剪贴板图像转两条产物：PNG 字节（vision 直喂）与 WinForms `Bitmap`（OCR）；透明区域铺白后再喂 OCR；
  - 翻译/精讲两条流的循环里加 `if (!cancellation.IsCancellationRequested)` 守卫，避免取消前已缓冲的片段插进复用面板的新内容开头；
  - `ApplySettings` 分别比对 `Capture` / `Paste` 并各自重注册；单个热键注册失败只气泡提示，不回退旧键、不 rethrow，其余设置照常落盘；
  - `SuspendCaptureHotkey` 改为按「正在录制的热键」注销对应实例；
  - `OnStartup` 的 Console 行同时报两个热键；
  - 托盘菜单加「选取翻译」（走 paste 链路）；左键单击打开设置，替掉双击。
- `App/Settings/HotkeyPage`（.xaml + .cs）：第二个录制框，分别绑定 `Capture` / `Paste`，各自一条状态行；paste 录制框支持 Esc 解绑（落空串，`CoerceGesture` 对该框放行空值），capture 录制框 Esc 仍是取消并保留原键；`Validate` 分别校验两个手势；文案泛化并补 F1–F12 单键提示（单 F 键会全局接管该键）。
- `App/Controls/HotkeyRecorderBox.cs`：新增 `AllowUnbind`（Esc 落空串＝解绑）与 `EmptyHint` 依赖属性，`CoerceGesture` 只对放行解绑的框允许空值。

- `Config/ConfigStore.cs`：`Normalize` 里 `TranslateClipboard` 的 null 收敛改到 `Paste`；`Paste` 不做空值兜底（空串＝关闭），`Capture` 兜底不变。

## 真机验收

- 选区读取：Chrome/Edge、VS Code、Windows Terminal、资源管理器地址栏、Electron 应用、窗口/无边框游戏。
- 剪贴板文本：「复制一段文本 → 按热键 → Ctrl+V 仍是原文」。
- 剪贴板图像 × 两档配置（`supports_vision` 勾/不勾）：前者直喂且剪贴板不动，后者 OCR 且剪贴板变成原文。
- 「无选中内容的程序按 Ctrl+C 会写空串」的清单记录：这是唯一会清空用户剪贴板的场景，靠还原兜底。
- F1 单键注册后的主观体验；录制中按 Esc 解绑 paste 后热键失效。
- paste 配成已占用组合、paste 与 capture 配成同一组合：托盘气泡、程序不崩、另一热键仍可用。
- 框选进行中按 paste：本次触发被丢弃。
- 连按 paste：只跑一轮。
- 热键到面板可见的手感（无选区分支约 600–700ms）。
- 托盘左键单击开设置；「选取翻译」菜单项可用。

## 遗留

- 模拟 Ctrl+C 各环境实测结论；UIPI/提权窗口下 `SendInput` 被拦时的回落表现。
- 超大剪贴板图未缩放。
- 面板位置不持久化，每次以光标为锚点。
- 剪贴板快照的实现取舍：`Clipboard.GetDataObject()` 返回的 `DataObject` 背后是剪贴板的 COM 代理，别的程序一改写剪贴板，代理数据就可能被释放，直接拿它还原会拿到垃圾甚至抛异常（自测里表现为偶发失败）。因此快照改为在改写发生前按格式把内容搬进进程自持内存（`ClipboardSnapshot.Capture`），还原时用自持数据重建 `DataObject` 并以 `copy: true` 落回剪贴板；读不出来的格式逐个跳过，不影响其余格式。
