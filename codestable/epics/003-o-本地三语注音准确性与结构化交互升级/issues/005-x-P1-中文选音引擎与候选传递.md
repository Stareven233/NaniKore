# P1 中文默认选音引擎与候选传递（自研词组匹配）

> **读者：** 接手中文注音链路的人——要做成什么、为什么不走 MeCab、数据从哪来、边界怎么守、怎么验、关闭回写哪里。
> **归属：** 本文件路径即归属 Epic 003。
> **来源：** Epic 003 活规格的 P1 中文选音；`codestable/tools/chinese-phrase-eval/README.md` 的合并词组方案证据；本会话与主人讨论（决定弃 zh MeCab，自研 pypinyin 式匹配器）。

## 做成以后是什么样

中文默认选音改为**进程内自研词组最匹配引擎**（不再依赖 NMeCab + `mecab-dict-index` 编译的 `sys.dic`）：

- 固定 13 个中文目标 + 现役中文自测样例全部命中（含此前读错的「还 / 罅缝」，且不回退「俳佪 / 周长大于」）；
- 每字产出「默认音 + 候选读音集合」，候选落到 `AnnotationSyllable` 并标出默认项，供后续 P2 hover/多音查看，本轮**不做** P2 UI；
- 展示、复制、收藏、选区全程只用**原文 code point + UTF-16 区间**；繁体 t2s 只作用于查音，不改写原文；
- 缺数据时软降级为纯文本，不影响翻译主链路。

**范围：** 自研中文读音引擎（词组表 + 单字频率默认 + CC-CEDICT/Unihan 稀有变体覆盖 + 繁体 t2s）、构建期数据合并产物、`AnnotationSyllable` 候选契约、`ChinesePinyinAnnotator` 重写、过滤/去重/短文本/`CountWords` 口径沿用、Debug + NativeAOT 验证。
**不包含：** P2 橙色提示色 / hover 菜单 / 手动纠音 / 个人读音偏好；姓名/自定义词典；口语连读变调；日/英引擎改动；英语候选正式 SQLite 迁移。

## 为什么现在做 / 当前坏在哪

现状中文 = NMeCab + CC-CEDICT/Unihan 编译的 `sys.dic`。运行期 MeCab 只回 Viterbi 选中的单个读音，同词面多读音靠「固定成本 + 1×1 连接矩阵」竞争，语境消歧弱，导致：

- 「他还在这里」的「还」读成 `huán`（应 `hái`）；「罅缝」读成 `xià féng`（应 `xià fèng`）。
- `AnnotationSpan`/`AnnotationSyllable` 只有默认项，没有候选集合，P2 无从开展。

`tools/chinese-phrase-eval` 已用固定 13 目标证明：pypinyin（纯数据词组 + 单字频率默认）+ OpenCC t2s 达 12/13，且**合并 CC-CEDICT 稀有变体（佪 huái）/繁体**可覆盖 13/13。故转向「合并词组词典」的纯数据方案。

## 现状怎么工作

纯原文 → `ChinesePinyinAnnotator.BmpSegments`（代理项边界切段）→ NMeCab `Parse` → 每个词条 `Feature` 取拼音 → `ParseSyllables` 逐字 → `AnnotationSpan(Start,Length,Reading,Syllables)`。过滤/去重/短文本由 `AnnotationProfile` + `AnnotationContext.ShouldEmit` 裁决；`CountWords` 与 `Annotate` 共用分段口径。

## 参考与数据源（已探明）

- **csharp-pinyin**（`resources/phonetics/csharp-pinyin/`）：pypinyin 的 C# 移植，可作**算法与词表格式参考**：最长匹配 2–4 字、`word.txt`(单字候选) / `phrases_dict.txt`(词组逐字音) / `trans_word.txt`(t2s) / `phrases_map.txt`(多音字集合)、`PinyinRes.candidates`。**但不可直接复用**：数据是 CC-CEDICT 2023-04-16 裁剪版，`佪` 只有 `huí`（无 `huái` 候选）、无 `俳佪` 词条；`SplitString` 只认 0x4E00–0x9FFF 会丢扩展字/标点，且 `PinyinRes` 无 UTF-16 偏移。→ 定位为参考，自研入口负责偏移与代理项。
- **数据统一放** `resources/phonetics/<子目录>/`，便于统一管理与更新：
  - `pypinyin/`：`phrases_dict.json` + `pinyin_dict.json`（目标版本 0.55.0，SHA-256 记录）。
  - `cc-cedict/`：`cedict_1_0_ts_utf-8_mdbg.txt`（固定日期快照 + SHA-256）。
  - `unihan/`：`Unihan_Readings.txt`（用于稀有单字读音兜底）。

## 方案与实现安排

1. **构建期合并**：读 pypinyin 词组表 + 单字候选，叠 CC-CEDICT/Unihan 稀有单字读音覆盖，折叠繁体 t2s 映射，压成一张紧凑运行期表落 `deps/phonetics/zh/`（沿用「按语言下载、哈希即版本」，进 `PhoneticDependencyManifest`）。产物不再依赖 `mecab-dict-index`。
2. **运行期引擎**（重写 `ChinesePinyinAnnotator`）：复用 `BmpSegments` 切段 → 每段最长匹配（多字词组优先，命中取该词逐字音；未命中断单字默认）→ 每字「默认音 + 候选」并保留**原文 UTF-16 绝对偏移**。
3. **候选契约**：`AnnotationSyllable` 增候选列表（含默认项标记）；`AnnotationSpan` 保留默认 `Reading`，需要时由 syllable 汇总。候选来源=单字多音候选 ∪ CC-CEDICT 变体，范围=词典收录读音，不凭空造。
4. **口径沿用**：`AnnotationProfile`/`AnnotationContext`（停用词、常用字符表、短文本全注、去重）、`CountWords` 分段，全部沿用；分段单元由「MeCab 词」换成「最长匹配词」，须保证既有自测不破。
5. **展示分离**：t2s 仅查音；展示、复制、收藏、选区只用原文 code point + UTF-16 区间。
6. **分发与许可**：pypinyin(MIT) + CC-CEDICT(CC BY-SA 4.0) + Unihan(Unicode) → 更新 `NOTICE` 与 `notes/phonetics-pipeline.md`；新数据文件进 manifest 与 ModelScope 同步清单。
7. **有界简化**：仅覆盖词典收录读音；未登录字保留原文纯文（与现状一致）；姓名/自定义/变调不做。

## 质量承诺

- **功能适宜性：** 13 目标 + 现役中文自测命中；区分「已验证 / 失败 / 未覆盖」，不把候选齐全误称语境消歧完成。「俳佪」靠 CC-CEDICT `huái` 覆盖，是硬约束不能回退。证据：`codestable/tools/` 可复跑对照 + `./scripts/dev.ps1 test`。
- **交互能力：** 结构不靠 `底字[读音]` 反推（承接 P1 已建区间结构）；候选挂 syllable，P2 可据此指认默认项。证据：结构化 spans/候选自测。
- **兼容性与可靠性：** Debug 与 NativeAOT 均能离线加载新数据、缺文件软降级纯文本、原文/偏移不改写。证据：`dev.ps1 build -Release` + 独立目录 `--self-test`；繁体 t2s 不改原文区间断言。
- **可维护性：** 数据来源、版本、许可、再生流程可追溯（`resources/phonetics/<子目录>` + `notes/phonetics-pipeline.md`）。证据：数据指纹与文档。
- **性能效率：** 记录数据体积、冷启动、稳态注音、内存，不预设未测阈值。证据：探针/自测耗时日志。
