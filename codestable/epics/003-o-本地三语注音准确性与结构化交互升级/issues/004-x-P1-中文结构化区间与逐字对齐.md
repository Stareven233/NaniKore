# P1 中文结构化区间与逐字对齐

## 本轮范围与依据

用户授权继续 Epic 003。P0 的 csharp-pinyin 固定目标实测为 12/13，生产为 10/13；候选虽改善三个目标，却将“周长大于”误选为成长读音，并存在原生字符串丢字、跨非汉字边界匹配与换行加载约束。本轮不采用该候选、不替换生产词典，继续推进与选音引擎无关的结构化切片。默认选音的“还”“罅缝”仍须另有可靠证据后解决。

目标：本地注音的纯原文、UTF-16 区间和中文逐字音节持续传递至 Ruby 控件；“银行”只挂在银行上，未知 Feature 不得作为拼音展示，扩展字符不得破坏后续已知词。保留既有词级过滤、去重、短文本策略、复制和收藏行为。不实施 P2 多音候选 UI，不制造当前引擎未返回的候选。

## 实现安排与质量承诺

- **功能适宜性与可维护性：** 扩展现有 AnnotationSpan 的逐字映射，在标注器生成映射；面板以原文和结构结果为事实源，直接构建 Inlines，方括号仅作导出及现有 LLM 输入协议。固定 spans 和真实词典都验证银行挂载，原文包含字面括号时也不得被反解析改写。
- **交互能力：** 中文词级 Ruby 容器内部按字音列对齐，仍保留词级选区和复制动作。验证读音、带注音文本、纯文复制、编辑再注音与收藏选区，布局验证覆盖字音列和相邻文字。单字选区与 P2 hover 不在本切片范围。
- **可靠性：** 中文 Feature 拒绝未知占位与不匹配音节；非 BMP scalar/非法代理项切断 MeCab 输入，原始 UTF-16 偏移加回，不臆造扩展字读音。CountWords 与 Annotate 共享分段规则。异步回写必须匹配原文、请求和设置，reset/换语言/编辑/关闭不接纳旧结果。

沿用现有缓存/闲置资源所有者，不引入引擎路由或全局结果缓存。先完成结构与银行回归，再做中文逐字布局及 Unicode/未知项修复；通过 ./scripts/dev.ps1 test 和必要的 NativeAOT/真实控件检查。工具对照报告不能替代宿主验证。

## 本轮执行与验证

已扩展 AnnotationSpan / AnnotationSyllable，中文适配层生成绝对 UTF-16 逐字音节；面板直接保存纯原文与 spans，RubyDocumentBuilder 按区间构建 Inlines。中文词内按字音列布局，仍为一个词级容器；复制读音/带注音文本从 spans 导出，保留原文和换行，不再把本地导出反解析为事实源。LLM 现有方括号协议在输入边界解析。

未知占位 Feature、非法字符及音节数不匹配均拒绝；MeCab 输入在代理项边界切段，后续龃龉读音恢复，扩展字自身保留纯文。CountWords 共用分段，既有过滤/去重自测保持通过。面板配置快照、语言、编辑/reset 与请求失效有回归覆盖。无候选引擎切换，未制造候选集合。

本轮完成的是 P1 结构与 Unicode 切片，不代表整个 P1 选音/候选传递已完成；P2 hover、多音候选、完整人工交互和引擎决策仍有后续。
