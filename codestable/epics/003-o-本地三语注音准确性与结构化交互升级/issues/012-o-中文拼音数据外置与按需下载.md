# 012 中文拼音数据外置与按需下载

> **2026-11-16 目标修订（主人复核计划时的取舍纠正）：中文不再随程序集内嵌，改为与日英及其他语言一致的「放 `deps/phonetics/`、设置页按需下载、闲置释放」形态。**
> 上一轮已完成的内嵌实现不作废，全部当作基础复用：数据字节、SHA-256、流式装载、金样本与内存基线都留着，改动集中在「数据从哪读 + 状态机 + 设置页卡片 + 分发清单」四处。
> 文件名沿用历史叫法（"内嵌收口"）以免 Epic 表格与 talks 的链接漂移；若改名，连 `spec.md` 表格与 `talks/004` 第 72 行一起改。

## 当时为什么定成内嵌（复核记录，不是本轮约束）

翻遍计划，**没有 ABI、许可或性能上的硬约束**，只有产品取舍，出处如下：

| 出处 | 原文 | 说明 |
| --- | --- | --- |
| epic `spec.md` 第 71 行 | 「精简包内置中文、日英首次缺包行为正确」 | 验收条款要求不带 `deps/` 的精简包也能注音中文——这是唯一实质约束 |
| `talks/004` 第 8 行 | 「中文保留自研引擎，现有数据改为内嵌随包」 | 决策结论，未写理由 |
| `talks/004` 第 37/47 行 | 「主 AOT exe … 中文内嵌和宿主增量体积尚待实施测量」「中文内嵌大小以实施时现有产物实际字节为准」 | 内嵌体积当时只是待测项 |
| `talks/004` 第 51 行 | 「设置页本轮只设内置中文、日语包、英语包」 | 中文被当成无需下载的默认项 |
| 结构原因（推测，计划未明写） | 中文引擎是纯托管数据（1.5 MB gzip），而 `deps/` 那套下载、哈希、ABI 生命周期原本是为 21.8 MB / 8.9 MB 的原生 DLL 设计的 | 「1.5 MB 塞进 exe 最省事」大概是当时顺手的选择 |

结论：纯粹为了「主力源语言开箱可用、少一个下载步骤」。本轮按主人决定改成外置下载，代价是精简包不再开箱注音中文（见「风险与取舍」）。

## 已完成可复用的基础（上一轮内嵌版）

- 数据字节与哈希：`zh_pinyin.txt.gz` 1,529,200 bytes / SHA-256 `2B5C68679BD393624D17B77BCA5734F9A608EB758FFA2F98D69D1DE0E520A981`，与 `deps/phonetics/zh/` 现有副本逐字节一致——下载物就是这一份，不需要重新生成。
- 流式装载：`TryLoad` 已改成「开一条流 → gzip → TSV → 解析」，只需把流的来源从 `GetManifestResourceStream` 换回 `File.OpenRead`。
- 自测基线：`cold=145–179ms / warm20≈0.0–0.1ms / rebuild≈150ms`、托管堆增量 31 MB、Debug 轮工作集约 595 MB——外置后冷启动只会多一次 1.5 MB 读盘，量级不变，可直接作为对比基线。
- 文档措辞与许可归属（NOTICE 3.3 三源合并说明）不用重写，只改「分发口径」那一句。

## 风险与取舍

- **精简包不再开箱注音中文。** 源语言为中/日/英时，中文用户首启必须先去设置页下载 1.5 MB；这是与日英对齐后的必然结果，需要在 Epic 验收条款里写明（第 71 行）。
- **多一条下载失败路径要验收。** 中文首次变成「可能缺包」的语言，需覆盖下载失败/取消/哈希错后仍是纯文本且翻译可用。
- **旧 MeCab 中文产物本就该清理。** `deps/phonetics/zh/` 里除 `zh_pinyin.txt.gz` 外的 `sys.dic/unk.dic/matrix.bin/char.bin/dicrc` 已不被读取，随 014 归档到 `.temp/`；外置后这个目录只保留拼音数据一份文件，语义反而更干净。
