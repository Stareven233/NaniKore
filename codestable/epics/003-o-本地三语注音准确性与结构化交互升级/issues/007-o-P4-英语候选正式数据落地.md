# P4 英语候选正式数据落地

> **读者：** 负责英语词典生成与运行期查询的人——编号候选怎样从解析层真正进入发布用 SQLite、默认口径怎样保持不变、分发哈希怎样更新。
> **归属：** 本文件路径即归属 Epic 003。**来源：** Epic 003 活规格 P4；P0 Issue 003 已验证候选数据形状（解析层 + 隔离内存契约保留 9,113 条编号备选、8,446 多读音词），尚未进入正式 SQLite。

## 做成以后是什么样

把 P0 已在内存验证的「同词面多读音 + 明确默认」真正落到发布用 `deps/phonetics/en/ipa_dict.db`，且**不改变本地 UI 现有单读音展示**：

- **候选进库：** SQLite 由单读音表改为 `(word, variant)` 联合主键的多行表，CMUdict 的每条编号读音（含 `(2)`/`(3)` 备选）都写入；默认读音仍为 `variant=1`。
- **运行期查询：** 新增 `EnglishIpaDictionary.LookupAll(word)` 返回该词全部候选（按 variant 稳定排序、每条过 `IpaTranscription.Normalize`）；`Lookup(word)` 语义不变——仍只返回默认读音（`variant` 最小者，等价原 `variant=1`），标注器与金样本行为不变。
- **分发：** 重新生成 `ipa_dict.db`、回填 `PhoneticDependencyManifest.EnglishFiles` 的 SHA-256；本地 `GetState("en")` 回到 `Ready`。上传 ModelScope 属操作性步骤（本机不可执行，留边界）。
- **只落数据：** 不改英语标注展示、不做橙色标记/右键异读列表、不做语境/词性/口音消歧。

**范围：** `PhoneticDictionaryBuilder.BuildEnglishDatabase`（schema + 写全量候选）、`EnglishIpaDictionary`（`LookupAll` + 默认查询）、`--build-en-data` 单独重建入口、`SelfTest.Phonetics` 候选库断言、manifest 哈希、`notes/phonetics-pipeline.md`。
**不包含：** 英语多音 UI（橙色/右键列表）、语义消歧、MisakiSharp 替换、`EnglishLemmatizer` 口径变更。

## 现状与依据

- 正式表 `words(word TEXT PRIMARY KEY, ipa TEXT NOT NULL) WITHOUT ROWID`，生成时 `if (!entry.IsDefault) continue;` 只写 `variant=1`；运行期 `Lookup` 用 `SELECT ipa ... LIMIT 1`。
- CMUdict 源（`cmusphinx/cmudict` `cmudict.dict`，3,618,488 字节，SHA-256 `81917843…C3D22`）不入库；本机 `.trash/english-candidates/cmudict.dict` 即该份快照。
- P0 已证明解析层（`CmuDictionarySourceParser`）与隔离内存契约（`EnglishPronunciationIndex`/`EnglishPronunciationCandidate`）可无冲突保留每词恰一个主项 + 若干编号备选。
- 历史 `ipa_dict.db` 条目是旧 wire format，`Lookup` 读出后过 `IpaTranscription.Normalize`；该归一对新口径条目幂等，重生成后自动空转。

## 设计决策

1. **Schema：** `CREATE TABLE words (word TEXT NOT NULL, variant INTEGER NOT NULL, ipa TEXT NOT NULL, PRIMARY KEY (word, variant)) WITHOUT ROWID`。单表、无外键；`(word, variant)` 已由 P0 证明无冲突，`INSERT OR IGNORE` 兜底。
2. **写全量：** 去掉 `IsDefault` 跳过，逐条按 `(word, variant, ipa)` 写入；`ArpabetIpaConverter` 不变，保证 `variant=1` 与旧产物一致（金样本不破）。
3. **默认查询：** `Lookup` 改 `SELECT ipa FROM words WHERE word=$w ORDER BY variant LIMIT 1`（`variant=1` 必存在，`ORDER BY` 仅兜底），读出仍 `Normalize`。
4. **候选查询：** `LookupAll` 增 `SELECT variant, ipa FROM words WHERE word=$w ORDER BY variant`，逐条 `Normalize` 后包成 `EnglishPronunciationCandidate`。
5. **重建入口：** 增 `--build-en-data`（只依赖 `deps/phonetics/_source/cmudict.dict`），避免重跑中文产物引入无关哈希漂移。
6. **哈希：** 重生成后回填 `EnglishFiles` 新 SHA-256；ModelScope 上传留操作性边界（本机无令牌/网络写权限）。

## 质量承诺

- **功能适宜性：** 候选进库后 `LookupAll` 对真实 `record`(3)/`lead`(2) 返回全部，默认项唯一且等于 `Lookup`；区分「已进正规 SQLite」与「尚未消歧」，不把候选齐全误称语境消歧。
- **可靠性与兼容性：** `variant=1` 产物与旧库逐字节等价语义（金样本 ubiquitous/abandoned/treason 不破）；DB 缺失/旧 schema 时 `LookupAll` 返回空、`Lookup` 软降级不抛；Debug 与 NativeAOT 均通过。
- **可维护性：** schema、数据源版本、哈希、再生命令写入 issue 与 `notes/phonetics-pipeline.md`。
