# 多语言提示词架构与智能字集探测

> **读者：** 负责实现字符集探测器、Prompt 插件组装与两阶段流式协议的开发者。  
> **归属：** `codestable/epics/001-o-学习型演进-精讲假名与生词库/spec.md` 切片 1。  
> **关联代码落点：** `src/NaniKore/Translation/PromptTemplates.cs`、`src/NaniKore/Translation/LanguageDetector.cs`。

---

## 做成以后是什么样

1. **智能字集探测器（`LanguageDetector`）**：
   - 接收纯文本输入，毫秒级探测所含语言特征（`Japanese`、`English`、`Mixed` 等）；
   - **平假名/片假名匹配**：包含 `[\u3040-\u309F\u30A0-\u30FF]` 直接判为含日文；
   - **纯汉字日文启发排查（解决「進入禁止」误判）**：
     - 若全句为 CJK 统一汉字（无假名）：排查是否包含“简体中文独占字集”（如“这、个、们、时、经、让、从、说”等不与常用日文汉字重叠的典型字）；
     - 若命中简体字独占特征 → 判为纯中文，不注入注音；
     - 若未命中简体字且当前为默认日中翻译偏好 → 判为纯汉字日文，注入日语假名注音插件。
2. **两阶段模块化 Prompt 组装**：
   - **Base Prompt**：定义流式输出极简分隔标记（`---TRANSLATION---`）与格式规约；
   - **语言特化插件（Plugins）**：
     - 日语插件：严格约束 **振假名标注 (`汉字[假名]`) + 动词原形（辞书形）**，严禁使用“未然形/连用形”等过时传统文法术语；
     - 英语插件：严格约束 **国际音标 (IPA) + 动词原形**；
   - **目标语言对齐**：动态替换 `{{target_language}}`，强制解释与译文采用目标语言。
3. **自动化单测覆盖**：
   - 自测用例覆盖：纯平/片假名、汉字假名混排、纯汉字日文词条（如「入場禁止」「案内図」）、纯简体中文句子、纯英文短句、日英混排短句。

**范围：**
- 包含：字符探测逻辑、提示词拼接、两阶段系统提示词定义、单元测试。
- 不包含：UI 假名富文本排版（由切片 2 承载）、会话网络流式收发（由切片 3 承载）。

---

## 为什么现在做 / 当前坏在哪

- **现状局限**：目前 `PromptTemplates.cs` 仅有单一静态翻译提示词，不仅无法支持假名注音（`汉字[假名]`），也缺乏两阶段精讲协议；
- **基础底座**：字符集探测与 Prompt 协议是后续所有富文本假名排版（切片 2）、缓存复用（切片 3）与微卡片提取（切片 4）的前置契约。

---

## 现状怎么工作

当前 `NaniKore.Translation.PromptTemplates.GetSystemPrompt` 仅根据请求类别（Translate / Explain / VisionOneshot）返回单一写死的英文系统提示词，通过 `ExpandTargetLanguage` 将 `{{target_language}}` 替换后直接发给大模型。不支持根据文本特征动态组装特化插件。

## 动哪些、验哪些

- **必须改/新建**：
  - `src/NaniKore/Translation/LanguageDetector.cs`：实现字符探测与简体排查启发算法；
  - `src/NaniKore/Translation/PromptTemplates.cs`：重构支持 Base + Plugin 架构；
  - `src/NaniKore/Diagnostics/SelfTest.cs` 或独立测试：覆盖各种语言样例的断言。
- **需要验**：
  - 日文常见短句能否正确被标记为 Japanese；
  - 纯汉字日文词条（如「進入禁止」「攻撃力」）是否正确注入注音插件；
  - 纯简体中文句子（如「今天天气很好，我们去散步」）不会被误注音；
  - 英文及日英混合句子能否正确拼接对应插件。
- **边界约束**：
  - 纯内存静态/轻量算法，零外部第三方词典依赖。

## 实现进展与验证记录

### 1. 执行痕迹
- **`src/NaniKore/Translation/LanguageDetector.cs`**：
  - 新建字符集探测器，提供 `LanguageFeatures` 与 `LanguageDetectionResult`。
  - 核心算法结合平片假名（`\u3040-\u309F` / `\u30A0-\u30FF`）和拉丁字母匹配，以及基于 **Unicode 10 个简体独占偏旁连续区间（言/纟/钅/门/马/车/贝/页/风/鸟） + 高频简体独占字表（`SearchValues<char>`）**的启发式排除算法。
  - 完美解决「進入禁止」「案内図」「攻撃力」「取扱説明書」等纯 CJK 汉字词条在日译中偏好下无假名时的注音插件注入，同时杜绝简体中文句子（如「今天天气很好，我们去散步」）误注音。
- **`src/NaniKore/Translation/PromptTemplates.cs`**：
  - 重构提示词系统为模块化 Base + Plugins 架构；
  - 定义两阶段流式极简分隔哨兵：`TranslationSentinel = "---TRANSLATION---"` 与 `TranslationSeparator`；
  - 注入日文插件（严格约束方括号振假名 `漢字[かな]` 与辞书形动词原形，严禁“未然形/连用形”等过时术语）；
  - 注入英文插件（约束 IPA 国际音标与动词原形）；
  - 注入目标语言强约束与精讲微结构化规约（预置于系统提示词，使第一阶段与后续精讲第二阶段保持前缀一致，100% 命中大模型 Prompt Cache）；
  - 支持读取用户自定义的 Base 提示词与各语言特化插件，保留视觉分栏与旧版全量提示词历史兼容性。
- **`src/NaniKore/Config/AppConfig.cs`**：
