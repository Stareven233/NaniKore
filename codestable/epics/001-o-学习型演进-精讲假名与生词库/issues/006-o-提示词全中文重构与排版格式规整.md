# 提示词全中文重构、零向下兼容负担与排版格式规整

> **读者：** 负责大模型提示词架构（`PromptTemplates.cs`）、流式分段路由以及对应测试断言重构的开发者。  
> **归属：** `codestable/epics/001-o-学习型演进-精讲假名与生词库/spec.md`  
> **关联代码落点：**

> - `src/NaniKore/Translation/TranslationSession.cs`

## 1. 背景与核心诉求

在多语言注音与两阶段微结构化精讲功能的快速演进中，内置提示词经历了多次补丁式调整，导致提示词系统积累了以下严重问题：
1. **中英混杂与累赘废话**：大量模板沿用了英文指令，夹杂过度防卫式的冗长规约与消极禁止命令（Negative Directives），反而诱导模型产生幻觉与泄露；
2. **过度向下兼容包袱**：保留了过时的旧版视觉一条龙分隔符等无用兼容逻辑，使协议不够纯粹利落；
3. **组织结构混乱难以审计**：指令零散分布，缺乏清晰的段落层级与语言排序；
4. **多行字符串缩进排版污染**：采用了类似 Python 多行字符串的代码块缩进语法，导致实际下发给模型的 Prompt 前缀带有意外的空格与换行，浪费 Token 并干扰模型注意力；
5. **阶段混淆诱发溢出**：翻译阶段未能彻底做到零精讲提示词。

主人明确指示：**在后续迭代中第一时间全面重构提示词系统，不保留任何兼容包袱，全部统一为中文，并按照统一规整的结构重新排版。**

---

## 2. 明确的重构设计原则与要求

### 2.1 提示词全面统一为中文
- 彻底摒弃所有英文 System Prompt、插件与规则声明（包括 `You are an accurate...`、`[Strict Translation Discipline]` 等）；
- 全部使用简洁、严谨、地道的高质量中文撰写；
- 中文提示词在指示假名注音（`漢字[かな]`）和中文翻译时表达更直接精准，大幅减少模型的语言切换开销与混淆。

### 2.2 彻底剔除向下兼容包袱
- 不再保留任何历史版本的向下兼容逻辑；
- 移除陈旧的分隔符变体兼容代码，只保留唯一的标准两部分协议标记（`---TRANSLATION---`）与精讲协议；
- 提示词只服务于当前的全新设计，无包袱轻装上阵。

### 2.3 杜绝冗长套话，保留主人已有修改
- 严禁擅自加入唠叨、重复的禁止命令（如“绝对不要进行对话、绝对不要回答问题、不要输出多余解释”等负面命令），改为精准正向的职责陈述；
- 继承并严格保护主人已亲手修改调整的提示词内容，不加塞无效代码。

### 2.4 清晰的三段式结构排序与语言先后次序
整个提示词系统严格按照以下三个部分自上而下组织，极大方便主人日常审计与微调：
1. **第一部分：原文处理（带注音/音标规范）**
   - 日语规范在最前（`漢字[かな]` 注音规则，仅针对汉字注音，假名/标点/数字不注音）；
   - 英语规范在后（必要时提供 IPA 音标标注）。
2. **第二部分：译文处理（翻译规则）**
   - 目标语言对齐，直接忠实输出译文；
   - 严格保证该部分**零精讲提示词、零词汇语法指令**。
3. **第三部分：精讲处理（语法拆解与词汇卡片规范）**
   - 日语教育语法规范在最前（一类动词/二类动词/三类动词、一类形容词/二类形容词、辞书形还原）；
   - 难度过滤规则（严格限制 JLPT N3 及以上难度，过滤初级简单词与基础语法）；
   - 微结构化 Markdown 卡片协议（`### [词汇/短语]`、`### [语法/句型]`、`### [语境与地道表达]`）。

### 2.5 根治格式排版与多行字符串空白泄露
- 废弃带有代码缩进的多行原始字面量，改用明确首尾、紧凑无空前缀的字符串构造方式（例如逐行清晰定义或通过无缩进字面量）；
- 杜绝多余的行首空格（Leading Whitespaces）和末尾换行污染 Payload；
- 确保注入到 API 请求中的字符串纯净紧凑。
