## 做成以后是什么样

1. **振假名（Ruby）只读富文本排版**：
   - 原文区以 `FlowDocumentScrollViewer` 承载，汉字上方整齐排布注音小字平假名/片假名（或英语音标）；
   - 汉字底字与周围纯文本基线完美对齐；
   - 拖选与复制体验：
     - 常规拖选支持直接复制日文或假名；
     - 拦截 Ctrl+C 与 Copy 命令，提取纯正文文本写入剪贴板（克服 WPF 默认跳过 `InlineUIContainer` 的限制）；
     - 右键菜单提供：`复制纯日文`、`复制带注音文本`（`汉字[假名]`）、`复制纯假名读音`、`全选`。
2. **生命周期联动 `AutoTranslate`**：
   - **开启“OCR 后自动翻译”**：OCR 识别完成后**直接以 `FlowDocument` 呈现**，阶段 1 流式接收注音文本并实时排版，流式结束直接呈现完整的振假名，杜绝从原生文本框到富文本的突兀跳闪；
   - **未开启“OCR 后自动翻译”**：保持原生只读/编辑 `TextBox`；用户主动点击右上角 `[翻译]` 后，才升格为假名 `FlowDocument`。
3. **原地无缝编辑与防误删双模交互**：
   - **触发**：双击原文阅读区域即可原地无缝切换；
   - **原地切换**：无缝切换为原生 `TextBox`，**仅将光标（Caret）精准定位在双击处，严禁全选文本（防止误触键盘丢失整句）**；
   - **收拢与复原**：
     - 用户**未修改内容**而离开焦点（`LostFocus`）或按 Esc：**立即复原原有的振假名 FlowDocument 视图**；
     - 用户**实质修改了文本**：保持当前纯文本 `TextBox`，点亮并激活右上角 `[重译]`；点击重译后发起新请求并更新假名。
4. **按钮状态与流式通道鲁棒性**：
   - 初次打开面板时右上角按钮固定为“翻译”，翻译完成或改动文本后再变为“重译”；
   - Provider 无论纯文本翻译还是多模态 Vision 均启用 `SectionChannelRouter` 并支持 `---TRANSLATION---` 哨兵，首个注音片段到达前保留 OCR 占位文本，杜绝原文被白屏清空。

## 执行记录与实测缺陷修复

1. **语法解析器 `RubyTextParser`** (`src/NaniKore/Translation/RubyTextParser.cs`)：
   - 实现 `漢字[かな]` 方括号振假名规约解析；
   - 智能识别汉字连续底字（支持 CJK 统一汉字、扩展区及叠字符号 `々`），准确处理 `ここは通[とお]れないよ` 中的前置假名与汉字底字；
   - 支持英文单词与 IPA 音标标注（如 `apple[ˈæpl]`）；
   - 过滤代码中括号（如 `arr[0]`）与无底字的孤立括号；
   - 实现 `ToPlainText`、`ToReadingText` 与 `ToAnnotatedText` 格式互转。
2. **振假名排版控件与文档生成器**：
   - `RubyInlineControl` (`src/NaniKore/App/Controls/RubyInlineControl.cs`)：上行小字注音，下行正文底字，设置 `IsHitTestVisible = false` 允许鼠标穿透拖选；
   - `RubyDocumentBuilder` (`src/NaniKore/App/Controls/RubyDocumentBuilder.cs`)：构建 `FlowDocument`，通过 `BaselineAlignment.TextBottom` 实现底字与周围纯文本基线平整对齐；
   - 解决 WPF 原生复制跳过 `InlineUIContainer` 的缺陷，实现 `ExtractFromSelection` 与 `ApplicationCommands.Copy` 定制提取。
3. **原文区双模态与防误删交互** (`src/NaniKore/App/ResultPanelWindow.xaml` / `.cs`)：
   - 布局改造：在 `Grid.Row="1"` 中重叠放置 `SourceViewerBorder` (`FlowDocumentScrollViewer`) 与 `SourceTextBox`；
   - 联动 `AutoTranslate`：
     - 开启时直接以 `SourceViewer` 呈现并流式打字，杜绝文本框跳闪；
     - 未开启时以原生 `SourceTextBox` 呈现供用户直接修改；
   - 原地编辑：双击原地切换为 `TextBox`，**精准定位光标，严禁全选文本**；
   - 失焦/Esc 还原：未修改离开焦点自动还原 `FlowDocument` 振假名视图；实质修改文本则保持 `TextBox` 并激活右上角 `[重译]`；
   - 右键菜单集成：`复制纯日文`、`复制带注音文本`、`复制纯假名读音`、`全选`。
4. **实测反馈缺陷修复**：
   - **缺陷 1：翻译按钮初次进入即为“重译”**：重构按钮状态机，`Reset` 初始进入始终置为“翻译”，翻译完成（`SetTranslationInProgress(false)`）或用户修改文本后才转为“重译”；
   - **缺陷 2：翻译后原文区被清空、无假名标注**：
     - 根因 A：三大 Provider（OpenAI/Gemini/Claude）原先仅在 `ImagePng.Length > 0` 时创建 `SectionChannelRouter`，导致纯文本请求下 `SourceText` 通道零输出；修复为当 `request.Kind == UnderstandKind.Translate` 或有图像时均挂载路由；
     - 根因 B：`SectionChannelRouter` 缺乏对 `---TRANSLATION---` 哨兵模式的匹配；修复为支持 `---TRANSLATION---` 及其变体并扩大滑动窗口到 23 字符；
     - 根因 C：`ResultPanelWindow.BeginTranslation()` 原先清空已有原文，若无注音增量到达则白屏；修复为保留 OCR 占位文本，直到收到首个 `SourceText` 增量才平滑替换；
   - **缺陷 3：移除多余的纯文本按钮**：从 XAML 和后台代码彻底移除 `SwitchToTextButton`，统一收敛为双击原地切换编辑，界面更精简纯粹。
5. **自动化测试与回归覆盖**：
   - `SelfTest.Translation.cs`：覆盖 `RubyTextParser` 各种边界和互转，以及 `SectionChannelRouter` 跨帧匹配 `---TRANSLATION---`；
   - `SelfTest.Ui.cs`：覆盖 FlowDocument 构建、AutoTranslate 联动、光标不全选、双击原地编辑、失焦还原与修改重译、流式增量更新及完成状态。
