## 闭环成果与修复总结（2026-09-19）

1. **彻底推翻旧兼容包袱，收敛为纯粹模块化提示词架构**：
   - 彻底从 `PromptConfig` 与 `AppConfigCloner` 中抹去单体 `Translate` 遗留属性；
   - 移除 `LegacyDefaultTranslatePrompt` 与 `IsLegacyTranslatePrompt` 兼容函数；
   - `PromptTemplates.GetSystemPrompt` 绝不向后探测旧单体提示词，翻译任务 100% 走 `BuildModularSystemPrompt` 动态拼装（注入 `JapanesePlugin` 振假名规则与严格翻译纪律）；
   - 设置面板 `TranslationPage` 仅展示与保存模块化 `Base` 及语言插件。
2. **重整“规范化”与主按钮状态机心智模型**：
   - 在 `ResultPanelWindow.OnNormalizeSourceClick` 与 `OnSourceTextBoxLostFocus` 中增加 `_translationHasContent` 判定；
   - 未产出有效译文前（`!_translationHasContent`）：无论点击“规范化”还是编辑失焦，主按钮严格锁定为**“翻译”**，状态与角标绝不出现“重译”；
   - 产出有效译文后（`_translationHasContent`）：用户实质修改原文或规范化后，主按钮激活为**“重译”**，重译发起/完成后恢复为**“翻译”**。
3. **流分流器（SectionChannelRouter）健壮性与假名链路全面贯通**：
   - 在 `DefaultTranslationBasePrompt` 中明确约束大模型不要输出 `<annotated_source>` 或 `<translation>` 字面 XML 标签；
   - `SectionChannelRouter` 支持 CRLF 与 LF 混合换行匹配，哨兵匹配全面采用 `StringComparison.OrdinalIgnoreCase`；
   - 新增 `StripSourceTags` 与 `StripTranslationLeadingTags`，在分流交接时刻立即剥离前导与闭合标签，杜绝流式冲洗切割标签导致标签残留的问题。
4. **消除 32 字符缓冲，恢复即时打字机流式体验**：
   - `SectionChannelRouter` 进入 Translation 阶段后，废除原 32 字符保留逻辑；
   - 引入 `GetSafeTranslationFlushLength`，仅在尾部可能处于未完结标签（`</translation>` 或代码块栅栏）中间时保留前缀，其余正文字符即时 0 延迟刷新至 UI；
   - 彻底解决短译文在 SSE 阶段被截留导致“等了很久原文与译文才同时蹦出”的体验缺陷。
5. **假名/汉字分离复制与选区精准提取**：
   - `RubyDocumentBuilder.ExtractFromSelection` 补齐 `TextPointerContext.ElementStart` 与 `EmbeddedElement` 分支支持，并引入 `visitedRubies` 集合去重，使划选包含 ruby 的词段能精准提取文字，绝不再误退为整句；
   - `ResultPanelWindow` 仅在选区为空时回退整句复制，并在选区存在时精准反馈；
   - `RubyInlineControl` 开启交互命中（`IsHitTestVisible = true`），假名支持鼠标手型与左键单击直接复制纯假名，汉字支持原生拖选，并提供专有右键上下文菜单（直达复制汉字、假名与带注音文本），并向状态栏发送即时提示。
