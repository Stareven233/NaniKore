## 现状与未决问题（2026-09-18 晚实测记录）

实测反馈依然存在以下未闭环问题，本 issue 保持 open 状态，留待明天集中攻坚：

1. **Bug 1：点击“规范化”按钮会导致“翻译”变成“重译”**：
   - 现象：用户截屏后打开面板，尚未发起翻译，顺手点击“规范化”整理空格，按钮立刻变成了“重译”，心智模型混乱；
   - 根因：代码在 `OnNormalizeSourceClick` 中无条件将 `TranslateButton.Content` 置为了 `"重译"`；
   - 解决原则：未完成首次翻译前，任何操作都不允许变成“重译”；或者彻底重新审视按钮语义，统一保持为简洁的“翻译”。
2. **Bug 2：界面仍然没有假名标注结果**：
   - 现象：用户实测翻译后，原文区依然只是纯文本展示，汉字上方没有振假名排版；
   - 根因排查重点：
     - 虽然修复了部分 prompt 路由，但当前用户运行环境下的真实请求可能仍未生效；
     - 需在明天直接跟踪/拦截真实 LLM 输出流，确认模型是否返回了 `漢字[かな]` 及 `---TRANSLATION---`，以及分流器与 FlowDocument 组装的真实交接情况。
3. **架构决策：彻底推翻旧版单体兼容包袱（关于 `IsLegacyTranslatePrompt`）**：
   - **定性**：`IsLegacyTranslatePrompt` 是防御性过度引入的“假兼容历史包袱”。
   - **决策**：**NaniKore 是积极演进中的现代项目，绝无历史包袱，严禁为了兼容老配置而写各种妥协探测代码！**
   - **明天执行方案**：
     - 全面铲除 `PromptConfig.Translate` 遗留字段；
     - 移除 `IsLegacyTranslatePrompt` 兼容函数；
     - 配置模型与提示词组装层彻底拥抱纯粹的模块化架构（`Base` + `JapanesePlugin` / `EnglishPlugin`）；
     - 绝不给旧版单体提示词留任何回退后门。

## 明天继续推进的明确步骤

1. **全面清退旧兼容层**：
   - 从 `PromptConfig`、`AppConfigCloner`、`ConfigStore`、`PromptTemplates`、`TranslationPage` 中彻底抹去单体 `Translate` 属性与旧默认值判定；
   - 整个系统对翻译提示词只认模块化 `Base` 与特化插件。
2. **重整“规范化”与“翻译”按钮状态交互**：
   - 无论是否点击“规范化”，在未产出有效译文前，主按钮固定为“翻译”；
   - 评估是否直接简化文案，消除“翻译”与“重译”来回切换的认知干扰。
3. **全链路真实流抓包验证假名标注**：
   - 增加精准调试追踪或单元测试用例，模拟真实模型 Profile（如 `dots3-note-prev`）的完整输入与输出流；
   - 确保从提示词注入 -> 模型返回带方括号文本与哨兵 -> `SectionChannelRouter` 分流 -> `RubyDocumentBuilder` 渲染排版全链路 100% 畅通。
