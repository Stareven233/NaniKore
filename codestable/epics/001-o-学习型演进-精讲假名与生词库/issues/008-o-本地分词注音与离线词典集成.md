# 本地分词注音与离线词典集成

> **读者：** 跨会话接手本地注音能力、离线词典下载分发与翻译流水线解耦的开发者。  
> **归属：** `codestable/epics/001-o-学习型演进-精讲假名与生词库/`  
> **前置讨论：** 用户指令讨论（解决小模型与翻译特化模型无法遵循原文注音指令的问题，将注音职责从 LLM 剥离至本地）。
> **评审决策（2026-10-03 复审）：** 初版本地注音支持中（简体）、日、英三语；繁体与韩语等留待后续；全语言统一「停用词/高频词不注」；重复词形同篇只注首现、异读补标；结果面板新增源语言下拉（默认自动检测，手选后重注）；纯原文为唯一事实源、注音只发生在渲染层；视觉路径模型只转录不注音。详见文末决策记录。

## 做成以后是什么样

1. **确定性本地注音体验**：
   - 用户在 `local_ocr` 或文本输入模式下，原文区由本地引擎即时（稳态毫秒级，首篇含词典加载）完成注音：日语全汉字标振假名 `漢字[かな]`、英语全拉丁词标国际音标 `word[/ˈɪŋklɪʃ/]`、简体中文全汉字标拼音 `漢字[pīn]`，直接渲染到 `SourceViewer`，无需等待大模型回传原文。
   - 注音过滤规则**全语言统一**：停用词与高频词不注——判据为「常用字符表（日语 常用漢字表 2010 版 2136 字 / 简体中文 通用规范汉字表 一级字表 3500 字）+ 每语言一份策展词级停用表（虚词、助词助动词、超高频动词）+ 英语手写停用词/高频表」，阈值可在设置调整，默认开启；同篇原文内同一词形只标注首次出现，若某次读音与此前已标注读音不同则补标（多音词按上下文自然处理，不维护多音词表）。判据数据与标注器之间隔一层「注音配置（AnnotationProfile）」抽象，后续可整体替换成语料词频表而不动标注器。
   - 不再依赖任何模型遵循字符级注音协议，消除幻觉、漏标、吞原文或格式崩坏。
2. **源语言下拉（新增交互）**：
   - 结果面板设置按钮旁新增「源语言」下拉，默认「自动检测」，可手选 `日本語 / English / 中文（简体）`；
   - 手选立即重新注音原文区；手选同时收口卡片收藏的默认语言口径（`ExplanationView` 取同一值）；
   - 手选语言若未下载对应词典，该语言部分软降级为纯文本并温和提示；下拉为粘性状态，直到用户切回「自动检测」。
3. **多语言插件化接口与扩展性**：
   - 抽象统一 `ITextAnnotator` 与 `TextAnnotatorRegistry`；初版交付 `ja`/`en`/`zh`（简体）三个标注器；
   - `ko`（韩语）、繁体中文等后续以新词典 + 新标注器接入，引擎与分发链路零改动。
4. **一个引擎、三份词典、按需分发**：
   - 全部语种共用纯托管 `NMeCab.Core` 引擎：日语用 IPAdic，中文用 CC-CEDICT 转译的 MeCab 词典（简体词面 + 词语拼音，多音字按词区分，未登录字回退单字默认读音），英语用扩充版 IPA 词典（含常见屈折形态直接收入）；
   - 零 Native C++ DLL 负担；离线词典统一收归于 `deps/phonetics/{ja,en,zh}/`，与 ModelScope 目录镜像，不设版本号别名目录；
   - 按语言独立下载：用户只下需要的语言，装哪个语言哪个语言 `IsAvailable`；体积以生成后实测为准并在交付说明中登记（日语词典编译态约数十 MB 量级，**本计划不承诺总包 15MB**）。
5. **一键下载与优雅软降级**：
   - 设置面板「原文注音词典」管理组，按语言展示状态、版本检测（哈希不符即提示更新）、ModelScope 一键下载与 SHA-256 完整性校验；
   - **未下载时**：自动软降级，原文区直接呈现纯文本，界面温和提示依赖未安装，翻译不受任何影响；
   - **已下载时**：懒加载即时生效，无需重启。
6. **双翻译路径适配**：
   - `local_ocr` / 文本翻译：LLM 提示词彻底移除注音规范与 `---TRANSLATION---` 分隔符，模型只输出译文，TTFT 与输出 Token 大幅下降；
   - `vision_oneshot`：提示词只要求模型输出**纯转录原文** + 分隔符 + 译文（不再要求注音）；客户端切分后，原文由本地引擎注音填充；若模型格式无法识别，整段内容兜底填入译文区，严禁丢字或白屏。

**范围：**
- 包含：本地注音抽象架构、NMeCab 引擎集成与三语词典、全语言停用/高频过滤、重复词形去重与异读补标、源语言下拉与手动重注、按语言词典下载/校验器、设置页管理、提示词与通道解耦、单元测试与自测金样本。
- 不包含：繁体中文、韩语及其他语种（引擎与分发已预留）；在线云端分词 API；词形还原大词典（英文屈折形态直接烧进词库，规则还原仅作最后兜底）；翻译内容与译文质量的任何改变。

## 为什么现在做 / 当前坏在哪

1. **小参数模型和专用翻译模型指令遵循劣化**：
   - 现行设计在 [`PromptTemplates.cs`](file:///F:/CODE/!projects/NaniKore/src/NaniKore/Translation/PromptTemplates.cs) 中通过系统提示词强行让 LLM 一边翻译一边在原文汉字/英文后打上方括号注音，并用 `---TRANSLATION---` 分隔。
   - 7B/14B 小模型或专用翻译模型（如 Aya、ALMA）执行此类复合元任务极其不稳定：经常丢掉分隔符、吞掉译文、给假名本身误打括号破坏语法树，或者把译文写到前半段。
2. **翻译延迟与 Token 成本浪费**：
   - 现行机制下大模型必须把原文逐字带注音完整吐一遍，才开始输出真正的译文，导致流式响应的首字延迟翻倍，且白白消耗大量输出 Token。
3. **视觉一条龙格式脆弱**：
   - 多模态模型遇到复杂图像排版时，很难严格按规定吐出带方括号的原文与分隔符，缺少容错与兜底机制。

## 现状怎么工作

```text
[选区/输入] ──> [LLM: Base + LanguagePlugins + Sentinel]
                      │ (流式输出: <annotated_source> + ---TRANSLATION--- + <translation>)
                      ▼
               [SectionChannelRouter]
               ├── DeltaChannel.SourceText  ──> SourceViewer (RubyDocumentBuilder)
               └── DeltaChannel.Translation ──> TranslationTextBox
```

- 原文注音完全耦合在 LLM 的输出流中，由 [`SectionChannelRouter.cs`](file:///F:/CODE/!projects/NaniKore/src/NaniKore/Translation/SectionChannelRouter.cs) 拆分；若 LLM 未输出 `---TRANSLATION---`，则容易导致路由错乱。
- 改造后（文本路径）：原文区在请求发起时即由本地引擎渲染，流式通道只承载译文。

## 方案与实现安排

### 1. 一个引擎、三份词典
- **日语**：NMeCab.Core + IPAdic 编译态（`sys.dic`、`unk.dic`、`matrix.bin`、`char.bin`、`dicrc`）。注意体积口径：IPAdic 编译态总量在数十 MB 量级，「总包 15MB」不成立；若后续需要瘦身，再用词频表自编精简词典（本 issue 不做）。许可需登记 NOTICE。
- **简体中文**：CC-CEDICT 转 MeCab 词典——生成脚本把词条（简体词面、拼音、词频元数据）转成 MeCab CSV 后，经固定版本的 `mecab-dict-index` 编译产出 `sys.dic`（编译只发生在离线生成期，App 运行时只读产物，运行环境不含 C++ 工具链）；NMeCab 直接复用同一引擎做中文分词，读音来自词条 feature。只收简体词面；未登录词走 `unk.dic`（单字默认读音表）；多音字由词面区分（行[xíng] 独立成条 vs 银行[yín háng]）。许可 CC BY-SA 4.0，需 NOTICE 与 About 署名。
- **英语**：见第 2 节。三语共用引擎与分发管道，`deps/phonetics/<lang>/` 只换词典不换代码。

### 2. 英语海量词库与查询
- **数据源**：Wiktionary IPA + CMUdict 扩充整合版（词条量 30 万~40 万+），**常见屈折变形直接在生成期展开收入词库**（abandoned、running、quickly…），单音词只存一个主读音（默认 en-US，生成期定音，不在运行期猜）；
- **存储**：压缩后编为轻量 SQLite（`word` 小写主键、`ipa`、原词形列），`Microsoft.Data.Sqlite` 已是项目依赖，零新增包；查询耗时 < 0.1ms；
- **分词规则**：仅对 ASCII 词元（字母、连字符、撇号）注音；跳过：已有方括号跟随的词、片假名、数字、无词条约定的缩写/专有名词；
- **规则还原兜底**：未命中时再尝试去 `-s/-es/-ed/-ing/-ly` 回查。因屈折已入库存，兜底仅处理长尾；注意不能用还原形态的重音替代原词（如 abandoned ≠ abandon 的应力），此为兜底而非主路径的原因。

### 3. 注音过滤与去重（全语言统一）
- **停用/高频判据（首版方案 C：规范字符表 + 策展词表）**：
  - 判据数据与标注器解耦：`AnnotationProfile`（源、阈值、开关）为唯一切面，升级为语料词频表（SUBTLEX/BCCWJ 类）时只换 profile 实现；
  - 日语：常用漢字表（2010 版 2136 字）字符级过滤 + 词级策展表（助詞・助動詞・超高频动词 する/ある/いる/いく 等）；
  - 中文（简体）：通用规范汉字表一级字表（3500 字）字符级过滤 + 虚词策展表（的了是吗呢吧…）；
  - 英语：手写停用词表 + 高频 top-N 表（两三千词量级，仓库内维护，无外部许可负担）；
  - 三张表随对应语言词典一起分发、一起 SHA-256 校验；N 与开关可在设置调整（默认「仅难词」开启）。
- **去重与异读补标**：`AnnotationSession` 记录本篇已注 `词形 → 读音`；同一词形再次出现且读音相同则不再注；读音不同则补标。多音词（日本語 行く/行う、中文 行 háng/xíng）无需词表，由「异读补标」自然正确处理。
- **失效条件**：原文变化、源语言 pin 变化、词典重装、过滤规则变化 → 全量重注。

### 4. 多语言插件化与路由门控
- 契约（保留 `ko` 等扩展位）：
  ```csharp
  internal interface ITextAnnotator
  {
      string LanguageCode { get; } // "ja", "en", "zh"（简体），预留 "ko"
      bool IsAvailable { get; }
      string Annotate(string plainText);
  }
  ```
- **Registry 分派**：默认按 [`LanguageDetector`](file:///F:/CODE/!projects/NaniKore/src/NaniKore/Translation/LanguageDetector.cs) 探测（含假名→日语；简体独占字→中文；纯拉丁→英语；纯汉字→日语候选）；用户手选源语言时按 pin 执行；
- **区段归属防误伤**：拉丁词元固定归英语注音器；CJK 歧义区段归探测/pin 语言；各注音器按序认领、span 不重叠、先到先得。中文注音绝不会误标日语汉字文本（除非用户手选中文），日语注音也不会污染简体中文；
- **与目标语言解耦**：注音是源文阅读辅助，不再做旧提示词时代的目标语言互斥剪枝；
- **纯原文唯一事实源**：`_annotatedSource` 仅作显示缓存；`SourceText`、收藏、精讲上下文、Session 的 `InitialSourceText` 一律只读纯文本。现有 [`RubyTextParser.StripRubyAnnotations`](file:///F:/CODE/!projects/NaniKore/src/NaniKore/Translation/RubyTextParser.cs) 的假名-only 剥离判据不再承接 IPA/拼音——因为注音结果根本不流入下游，这也顺带消除了「IPA 方括号漏进精讲 prompt 与收藏库」的隐患。

### 5. 词典生成、版本钉住与按需分发
- **本地与 ModelScope 目录严格镜像**，无版本号别名目录：
  ```text
  deps/phonetics/
  ├── ja/   (sys.dic / unk.dic / matrix.bin / char.bin / dicrc / stoplist)
  ├── en/   (ipa_dict.db / stoplist)
  └── zh/   (sys.dic 等 / stoplist)
  ```
- **生成流水线**：`tools/phonetics/` 脚本可重跑——产出三语词典与停用/频次表 → 计算每文件 SHA-256 → 生成 manifest（含来源、许可、生成日期）→ 上传 ModelScope `https://modelscope.cn/models/Noetuu/nanikore-deps/resolve/master/phonetics/...`。代码内 manifest 与产物一一对应，杜绝「不可重建」；
- **版本检测 = 哈希不符即提示更新**（不引入独立版本号体系，与 OCR 依赖一致）；
- **按语言独立下载/校验/落盘**至可执行程序同级 `deps/phonetics/<lang>/`（复用 `OcrDependencyPaths.ApplicationDependenciesDirectory` 模式）；用户只装需要的语言；
- **发布流水线**：`./scripts/dev.ps1 publish -full` 时整个 `deps/` 随包分发（必需依赖清单追加 phonetics 条目，防止漏件）；精简包用户在设置页按语言一键补全。

### 6. 视觉一条龙（`vision_oneshot`）协同与兜底
- 视觉 Base 提示词改为：只输出**纯转录原文** + `---TRANSLATION---` + 译文，删除一切注音要求；
- 客户端拆出转录纯文本后交给本地引擎注音填入原文区，译文走译文区；
- **格式不符（未识别到分隔）**：整段输出兜底填入译文区，原文区保留占位提示，严禁丢字白屏；
- 随之退场：`RubyTextParser.NormalizeRawAnnotatedText` 的注音清洗与 `CleanAnnotatedSourceWithInitial`（模型乱标注音的兜底在本地注音架构里不再有产生源）。

### 7. 性能与加载口径
- 词典懒加载 + 标注在后台线程执行（`Task.Run`），UI 线程只负责渲染；每篇原文在「原文 + pin + 词典 + 过滤规则」不变的前提下只注一次并缓存；
- 不写「3~5ms」这类拍脑袋数字：Phase 4 以实测登记（首篇含加载耗时、稳态每千字耗时、大文档注音密度压力，如单篇数千汉字时 ruby 内联量）；
- 源编辑/ pin 切换触发重注时同样异步 + 去抖，避免逐键重算。

## 阶段推进计划

## 验证

1. **日语金样本**：平片假名混合、动词变位、复合词与送假名边界（`躊躇[ちゅうちょ]した`、`買[か]い出[だ]しに行[い]く`）；同篇重复词形仅首现；同形异读补标；
2. **英语金样本**：常规词、生僻词（`ubiquitous`）、屈折词（`abandoned`，重音正确，走词典直查而非词形还原）；多音词（`read`/`lead`/`wind`）选音固定；缩写、专有名词、数字不注；停用词与高频词不注；
3. **中文（简体）金样本**：多音字按词区分（`行[xíng] 人` vs `银行[yín háng]`、`重[zhòng] 要` vs `重[chóng] 新`）；未登录字单字默认读音回退；虚词（的了是吗）与高频字不注；
4. **过滤与去重**：全语言停用/高频过滤生效、阈值配置生效；重复词形仅首现、异读补标；规则变化/原文变化/pin 变化触发全量重注；
5. **源语言下拉**：三种语言手选各自正确注音；错误手选（如日语句选「中文（简体）」）按 pin 执行并可切回「自动检测」恢复；手选语言未装词典时该语言部分软降级；
6. **软降级**：未装任何 `deps/phonetics/` 启动，原文区纯文本、翻译与 UI 正常；仅装单语言（如仅 en）时其余语言不注、对应语言正常注音；
7. **下载与热生效**：按语言下载、进度报告、SHA-256 校验失败重试、落盘即生效（无重启）；哈希不符提示更新；
8. **视觉兜底**：多模态模型返回无分隔符纯文本 → 全量落入译文区；有分隔符 → 转录原文经本地注音；
9. **回归**：`SelfTest.Translation` / `SelfTest.Ui` / `SelfTest.Config` 等全绿，含三个语言注音插件键退役后的配置兼容（旧自定义值解析不报错、不再注入）。

## 决策记录（2026-10-03 复审）

1. 初版本地注音限定 中（简体）/日/英；繁體中文、韩语等延后——引擎（NMeCab.Core）与分发管道按扩展预留，新语种只加词典与标注器。
2. 全语言统一「停用词/高频词不注」，取代原计划的「全部注音」；阈值走设置，默认「仅难词」。
3. 同篇重复词形只注首现；该次读音与此前已标读音不同则补标——以「异读补标」自然覆盖多音词场景，不维护多音词表。
4. 结果面板新增源语言下拉（设置按钮旁）：默认自动检测，手选即重注，粘性直到切回自动；同时收口卡片收藏默认语言口径。
5. 纯原文为唯一事实源，注音只发生在渲染层——收藏、精讲、Session 只读纯文本。
6. 视觉路径模型只转录不注音；`---TRANSLATION---` 仅视觉路径保留，Router 拆显式模式，文本路径直通。
7. 词典必须可复现：`tools/phonetics/` 生成器 + SHA-256 manifest + 许可 NOTICE（IPAdic / CC-CEDICT CC BY-SA 4.0 / Wiktionary IPA / CMUdict）；按语言独立下载、哈希即版本。
8. 体积口径实事求是，不承诺「总包 15MB」；性能以 Phase 4 实测登记为准，不写拍脑袋毫秒数。
9. 停用/高频判据首版取「规范字符表 + 策展词级停用表」（方案 C）：日语 常用漢字表 2010 / 中文 通用规范汉字表一级字表 3500 字 / 英语手写表，全随词典分发与校验；判据经 `AnnotationProfile` 抽象隔离，后续可按需升级为语料词频表（方案 B）而不动标注器。
10. 简体中文词典的 `mecab-dict-index` 编译只存在于离线生成期；运行时不依赖任何 C++ 工具链。
