# 注音架构：中文自研 + 多语 MisakiSharp（原生 DLL 按语言包）

> 2026-11-15 定稿。本文是注音升级的**唯一计划与决策记录**，取代旧的「P0–P4 自研中文 + IPAdic + CMUdict」方案。
> 穿刺证据：[notes/misaki-spike.md](../notes/misaki-spike.md)；探针源码：`codestable/tools/misaki-spike/`、`codestable/tools/misaki-native/`、`codestable/tools/misaki-native-client/`。

## 一句话

- **中文**：保留自研引擎（数据 ~1.5MB 内嵌随包，带多音候选）。
- **日/英 + 未来 5 语**：走 MisakiSharp，编成**原生 DLL**、**按语言裁成小包**、**放 ModelScope 按需下载、懒加载**。
- 界面注音**只取管线中间产物，绝不取 TTS 最终输出**；复用现有 `AnnotationSpan/Syllable/Candidates` + ruby + hover 结构，只换各语读音来源。

## 为什么

一个 Apache-2.0 的 C# G2P 包（MisakiSharp）覆盖 8 语、纯本地离线、AOT 可用；用原生 DLL 外置后主 exe 不膨胀、词典仍可像现在一样按需下载。中文因需要「多音候选」而 Misaki 偏偏缺这块数据，故单独保留一个小自研模块。

## 穿刺结论（实测）

| 维度 | 结论 |
|---|---|
| 中文 | 内部拼音表 43.3 万条，选音正确；但**单字多读=0**（20924 个单字只有唯一读音），对外只吐注音符号/IPA（TTS 用）→ 候选数据根本没有，只能自研提供 |
| 日语 | `JapaneseTagger.Parse` 公开，逐词 原文+片假名读音 → 可做振假名；UniDic 3.1.0；无音调核；最终 phoneme 已口语化 |
| 英语 | `Phonemize` 逐词 原文+IPA+置信度，词性/时态消歧强；**多音按「词性=音素」存在数据里，可直接取**；数字/缩写会展开，须按原 token 对齐 |
| 5 语 | espeak 蒸馏，单音素串，无逐词对齐、无候选 |
| AOT | MisakiSharp netstandard2.0，可编成**原生 DLL**；AOT 主程序 `LoadLibrary` 动态加载原生 DLL **可用**（托管程序集不可运行时加载） |
| 依赖 | MisakiNative.dll 只依赖 Windows 内置 UCRT + 系统 DLL，**无 VCRUNTIME/MSVCP，不需 VC++ Redist，纯便携** |
| 体积构成 | 内嵌资源 65.99MB：espeak 系 31.9、日 17.9、中 8.1、英核心 8.05 → 裁剪后日包~18MB、英包~8MB(+espeak +12)、5语包~22MB |

## 三语决策

- **中文：自研引擎**（issue 005）。有候选 + 逐字对齐 + hover 已验收，数据小，嵌入随包。
- **日语：Misaki `JapaneseTagger.Parse`**（unidic 3.1.0）出振假名。多音候选暂单读（unidic 枚举性价比低，需要时再做倒排表）。
- **英语：Misaki `Phonemize`** 默认读音 + **词性多候选**（直接取 Misaki 词典，弃 CMUdict）。
- **5 语：Misaki `EspeakG2P`**，单读音（无候选），质量一般。

## 分发与打包架构

```text
主 AOT exe（约现状大小）
 ├─ 应用 + 中文自研引擎（数据 ~1.5MB 内嵌）
 └─ 薄 P/Invoke 客户端（~1.5MB，运行时 LoadLibrary）
deps/phonetics/misaki/（ModelScope 按需下载）
 ├─ MisakiJa.dll      ~18MB  日语（unidic 3.1.0）
 ├─ MisakiEn.dll      ~8–20MB 英语（+espeak 回退可选）
 └─ Misaki5Lang.dll   ~22MB  西/法/印地/意/葡（espeak）
```

- **重打包**：用 Mono.Cecil 对官方 `MisakiSharp.dll` 构建期剥资源；每个包只留该语资源、只导出该语函数，NativeAOT 再裁掉无用代码 → 包小。升级=重跑剥资源脚本 + 重编（`fork 源码改 csproj` 为备选）。
- **加载**：原生 DLL 文件整体下载，但**运行时按语言懒加载**（首次用到某语才建表），内存不吃满。
- **设置页**：总开关「本地注音」；「中文注音」内置·就绪（0 下载）；「日语包 / 英语包 / 其他 5 语包」各自显示体积、下载/更新/就绪与进度。缓存落 `deps/phonetics/misaki/`，SHA-256 作版本。
- **兼容旧路**：旧的按语言下载 ja/en/zh 词典（`PhoneticDependencies`）由本方案取代；OCR deps 不动。

## 架构硬约束

1. **只取中间产物**，不取 TTS 最终输出（否则 は→wa、变调、数字展开污染界面）。
2. **一律按原文字符偏移对齐**（Offset/Span）；数字/符号展开不改变对齐基准。
3. **中途拦截**：日语用公开 `JapaneseTagger.Parse`；英语用 `Phonemize` 的逐词 token；中文走自研引擎（不用 Misaki 中文）。
4. **`InvariantGlobalization=false`**；AOT 烟测常态跑。
5. **各语 Lazy 单例**：包/语言首次用到才加载，热态复用。
6. **后台线程分批 + 轻量锁**（`Lock`/`SemaphoreSlim`），不阻塞 UI；封装层对 Misaki 静态初始化的并发首建加锁。
7. **只管“怎么读”，不管“啥意思”**：读音毫秒级先出；释义另走 LLM 异步通道。
8. **复用现有契约**：`AnnotationSpan/Syllable/Candidates`、ruby、hover 面板不动，只换 provider。

## 多音 hover 的统一与边界

- UI 与数据契约统一：`Candidates[0]` 即默认，hover 同套面板列「底字 读音」。
- 候选来源分语言：中文=自研引擎；英语=Misaki 词典（词性多读）；日语=单读（需要时补 unidic 倒排）；5 语=无候选。
- 能做到「同一套 hover UI、有多少候选显示多少」，做不到「每语都有多候选」——数据边界。

## 可执行路线（按序，全部要做的）

1. **重打包链**：Cecil 剥资源脚本 + 按语言出原生 DLL（ja/en/5语）+ 版本哈希 + NOTICE（含 UniDic 3.1.0 BSD 等）。
2. **主程序接入骨架**：P/Invoke 客户端 + 各语 Lazy 单例 + 后台/锁 + 设置页多语包下载 UI + AOT 烟测。
3. **日语接入**：`JapaneseTagger.Parse` 出振假名，保留 span 契约；送假名/长音/复合词/未登录/对齐回归。
4. **英语接入**：默认读音 + 词性候选，数字/缩写对齐回归。
5. **中文内嵌收口**：自研引擎数据由“下载”改为“随包内嵌”，核对与现网一致、候选/hover 复用。
6. **5 语接入**：EspeakG2P 单读音，按语种接入（无候选）。
7. **分发简化与收尾**：移除旧 ModelScope ja/en/zh 注音下载路径，打包体积/离线/AOT 回归，更新 `spec/index.md` 与 `notes/phonetics-pipeline.md`，关闭旧 Epic/issue。

## 工程默认值（可随时改）

- 英语包默认**带** espeak 回退（未登录词/人名更准，+约 12MB）。
- 重打包用 **Mono.Cecil 剥资源**，不做源码 fork（升级重跑即可）。
- 5 语包随第 6 步一起出（数据已具备，成本低）。

## 明确不做

- 中文切 Misaki（会丢多音候选）。
- 音调核展示、手动纠音、个人偏好、口语连读变调：不在本规划范围。
- TTS / OCR API：仅备忘，非承诺。
