# 三语现状基线（Epic 003 / Issue 001）

仅在仓库内运行的隔离控制台工具。直接链接生产 ja/en/zh 标注器、过滤/去重策略、IPA 规范化、格式化器、资源清单与 Ruby 解析器；不引用桌面工程、不修改生产资源、不下载、不再生词典。唯一宿主适配是 `RepositoryOnlyPaths.cs`：不引入 OCR，发布路径回落直接报错。链接文件中的下载器仅为编译资源清单存在，工具从不调用。

从仓库根目录运行（PowerShell）：

```powershell
dotnet run --project codestable/tools/phonetics-baseline/PhoneticsBaseline.csproj
```

工具使用 PATH 中的 .NET SDK（本机用户 `DOTNET_ROOT` 为 `D:/E_extension/csharp/dotnet`）。默认构建中间物进入工具目录的 `obj/`、二进制进入 `bin/`，均不提交；每次运行的 UTF-8 报告进入 `artifacts/phonetics-baseline/<UTC时间>/report.txt`，不会覆盖上次报告。控制台与报告包含相同的工具输出；SDK 构建错误由 dotnet 控制台给出。

退出码：`0` 没有检测到偏差；`1` 存在明确失败；`2` 依赖未就绪/身份不满足生产清单。未捕获异常也使运行失败。**0 仍不代表未覆盖项通过**。`KNOWN_FAIL` 是相对固定契约检测到的明确偏差，绝不是豁免成功或允许运行变绿的快照；工具不自动接受现状，也没有更新答案开关。

`Samples.cs` 固定 22 个样本，期望独立于运行输出：

- ja/en/zh 优先沿用 `SelfTest.Phonetics.cs` 已有金样本，明确标注其来源为回归契约。包括送假名、词形变化、IPA、难词过滤和重复去重。
- 中文手工语义标注：仍然的“还”=`hái`，归还的“还”=`huán`；成长的“长大”=`zhǎng dà`，周长大于中的相同连续词面“长大”=`cháng dà`；简繁“银行/銀行”=`yín háng`；“罅缝”=`xià fèng`。这些值由语义预先指定，本轮未联网核对权威词典版本；不宣称完整句子全部读音已经核验。
- 中文目标音校验允许分词边界不同：仅当生产 span 的字符数等于空格分隔音节数时，按 BMP 字符投影目标音节。无法对齐则报失败，不猜测映射。投影仅供检验，不能作为生产逐字映射证据。
- 混排、重复、CRLF/LF、扩展 B 字 `𠮷/𠀀` 均使用真实标注器；扩展字规范读音与是否应注音标为未核对。英文 Bob/device 完整 IPA 未核对，整句未固定答案时也单列未覆盖。

每条可执行样本输出 UTF-16 span 的 start/length/底字/读音、拼装文本、实际 Ruby 分段底字与读音，检查原文往返和 span→Ruby 一一挂载。`rare` 显式使用长文本过滤口径以复用 selftest；`filtered` 关闭难词筛选但保留停用词（银行样本）；`all` 强制短文本全注以观察选音，不经过语言自动探测、注册器缓存或实际词数阈值决策。每条使用新上下文，避免前一条的去重状态污染结果。

固定的最小失败反例直接复用 selftest 区间：`不行就去银行` 的 `(0,2,bù xíng)` 与 `(4,2,yín háng)` 拼成 `不行[bù xíng]就去银行[yín háng]`。链接的 Ruby 解析器向前吞掉连续汉字，第二段底字将是 `就去银行`，与预期 `银行` 不同。它独立于词典版本运行并保留失败；真实中文样本另外走完整标注器链路。静态可定位根因为 `RubyTextParser.FindBaseWordStart` 不知道原始 span 起点；原文往返正确不能证明挂载正确。

资源证据包含语言目录全部文件的字节数/SHA-256、生产清单状态、首次打开耗时、单次注音耗时和进程工作集。它们是一次进程观测，不是冷磁盘、稳态分位或完整内存基准。中文候选收益、NativeAOT/真实宿主、UI复制/选区/收藏、闲置释放重载、下载与再分发许可均明确未覆盖。
